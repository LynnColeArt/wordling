# Advance: clean synthetic coverage and optional historical oracle

`go test -count=1 -v ./internal/layout -run '^TestAdvance'` requires no private
Advance files. `TestAdvanceSyntheticLayout` authors fresh native documents with
public document APIs, checks absolute/right/down movement, bottom clamp, wrapped
print placement, and exported/reparsed layout. Expected coordinates and print
rows are explicit constants, not values generated by the implementation under
test. These are regression checks, not evidence of original DOS parity.

`TestAdvanceCapturedLayout` skips with an explicit unavailable message unless
`WORDLING_ADVANCE_REFERENCE_DIR` names an absolute directory. When supplied,
all three historical HORIZ.WP, BOUNDARY.WP and HORIZ.PRN files must exist and
match the SHA-256 pins in the test. Only those verified bytes are consumed.
A missing file or digest mismatch fails; there is no fallback to synthetic
results and no copying or staging of private reference files.

The pins identify the existing local Advance captures used by the prior tests.
They do not authorize distributing those captures. Original binaries, media,
and reference assets remain private. This change does not certify their license.

Scope is deliberately narrow. `advance.py` PTY comparisons and other existing
layout tests still require their separately supplied private reference fixtures.
For example, `TestStandardPrinterLineFormatMatchesDOS` reads mission1 line-margin,
line-format, note and other capture families. A clean synthetic Advance pass is
not a complete clean-checkout suite pass, an integrated PTY pass, or Mission 1
acceptance. The historical test and synthetic tests report separate outcomes.
