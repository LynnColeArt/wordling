## Structural qualification and knowledge

Approved40 starts with one printable ASCII sentinel before a document of token
shape ASCII / On / ASCII / ASCII / Off / ASCII. View precedes deletion of the
sentinel atg0. The operator opens history, performs exactly three Previous commands,
cancels atg0 in the same view, then supplies actual Right navigation as a grouping
separator before the researched target. No intervening Save, view command, typed
text, additional deletion or foreign history is accepted as that provenance.
The dispatcher reports actual successful Right/Save commands; the library does
not invent physical input delivery or a hidden session/router.

The implementation stores the actual deleted native ASCII value and code spans;
it never recognizes S/A/BC/D, file offsets/hashes or prerecorded screen rows.
The six-token shape and command provenance are deliberately narrow qualification
policies. Native character values are data: the pinned Reference Manual Delete
Codes112–113/PDF129–130 describes code versus character deletion, while approved23/
40 prove these command/shape effects on project scratch files. Printable ASCII
values cannot encode a formatting command in this admitted grammar. The component
therefore derives overlays and native transformations from actual immutable values;
a metamorphic data-identity test checks that changed printable values survive.
The pinned Reference Manual Undelete697–698/PDF714–715 additionally distinguishes
paired-code character deletions from other deletion methods, defines grouping by
cursor movement and documents bounded eviction. These documentary rules support
structural data operations and explicit movement barriers; they do not settle the
March executable's hidden-count or unobserved interleaving behavior.

That test is NOT another original observation or permission for wider token shapes,
attribute families, histories or ordering rules. Original captures remain literal.

Count() keeps its old stored-fragment-inspection meaning. New CountKnown() says
whether that number also models an actual stack count. It is false in bounded40
observations and after an unqualified history effect. Entry(i) in bounded40 inspects
stored observed fragments; its index is not a global original ordering assertion.
Preview.Index() is the observed browse POSITION in those contexts, not an entry
count. Four supported positions may all show the same stored plain fragment, or
alternate closing OnOff and the prior plain fragment. All overlays are assembled
from actual document tokens/native fragments; there is no screen replay table.
Extra Previous, non-newest Restore, repeat Restore, other cursor/view and continued
deletion/movement after a bounded observation refuse. One actual Restore and its
four post-Restore browse/cancel positions remain enabled. No hidden entry is
claimed absent; no period is converted into an absolute stack count.

Every public wrapper captures private immutable state: document, cursor, history,
question, preview and ASCII receipt. Whole-value wrapper replacement cannot rebind
an accepted object. Refusal publishes no partial document/cursor/history update.
No-edit preview/cancel/decline exports are exact input bytes. The sole publisher
keeps the OWNED input prefix/resources literal and sets only indexed packet6 bit3
where independently approved23/25 permits it. Approved40's later flag8 versus source0
is not attributed to the target alone. The65KiB/16K-token/two sequential nonnested
Bold-pair bounds are initial implementation/qualification policies, not original
format or DOS capacity limits. Above-bound Restore refuses before history change.

## Explicit unresolved EC045 intermediate

EC045's complete original sequence removes the pair then Deletes B and C, and its
newest Restore yields plain BC rather than an attributed fragment. It does not
inspect immediate history after the first pair removal. Approved40 supplies only
its pre-browsed Right-separated sentinel context; it does not fill that empty/
unbrowsed/uninterrupted intermediate. Generic empty-history pair deletion therefore
still refuses. There is no compound/lookahead API predicting future keys, guessed
code entry, automatic history clear or claim of complete EC045 support. The actual
complete-sequence witness remains linked by case-associations.json and approved
editing.md; a separately justified opaque-history contract/discriminator is needed
before that interactive path can be admitted.

Other unqualified branches include nonempty question/block declines, unknown
interleavings, arbitrary prior stacks/shapes, Backspace ASCII grouping, word deletes,
general block/edit/search/code families, repeated code Restore above the supported
bound, cross-document/global clearing/persistent history/redo, new documents,
physical keyboard/print metrics and other baseline/resources/languages. M2 PDF is
outside this work. Go library/native correctness, original candidate interoperability
and physical qualification remain distinct claims.
