## Closed profile data, broader resource supply and config ownership

Distinguish the historical application's private inputs, the independently authored **serialization metadata profile**, and actual Linux layout/printing resources. Original SET/PRS/DRS/EXE files or opaque blocks are not bundled. Documentary SET mappings above explain numeric/name/cache/stamp facts; they are not runtime reads. No additional blanket approval or generic hash algorithm is required merely to encode these individually qualified format facts. This is a technical scope choice, not a ruling about an unspecified proprietary asset.

The private profile contains typed name/enum/unit/flag/descriptor/cache/DOS-stamp values with per-field authority and exact supported constraints. It is independently authored from schema.json, not loaded/copied from an original native image or stored as a324-byte template. Names and cached values e724/c9/9338/87cf and6918/8a60 are narrowly scoped serialization facts associated with this profile. They do not assert that a matching printer/font file exists on the host, compute arbitrary caches, or claim independent rendering/metrics/resource generation. Original reference resources used by later validation remain privately supplied under the existing research setup.

Runtime `document.New` therefore needs only explicit supported profile selection; it performs no resource/file acquisition. Proposed shape remains `New(NewConfig) (*Document,error)` with a closed profile identifier such as `HistoricalUS51DosTextStandardPrinter`; zero/unknown profiles refuse. The public config has no raw field overrides, prefix/blob/offset map, mutable resource slices, arbitrary hash/stamp, source wrapper or IO capability. `HistoricalDosTextInitialization` is an internal typed policy of that profile, not four public integers that expand support accidentally. Same selected profile/config must produce deterministic native field values without consulting wall clock, filesystem timestamps or original resources.

Capture config/profile data privately before publishing a Document. Whole config/wrapper replacement, mutated getter values or changing caller buffers cannot retarget an accepted revision/profile. Shared profile data, if used, is private immutable data with bounded memory; public maps/slices or a mutable global profile setter are forbidden. Existing storage/source capability and Close rules remain intact. The closed profile owns no resource handle and needs no Close; a later dynamic provider would need separate qualification/immutable snapshot capture and actual Close semantics, never retroactive mutation of a document.

Different printers/fonts/locales/stamps/default settings and independently generated resource/descriptor/hash/metrics profiles remain unsupported until separately qualified. They may eventually use a separate lawful resource provider or independently generated resources; neither is smuggled into this constructor's scope. Supplying real Linux layout/printing resources remains M1 work even though native closed-profile construction can proceed without the proprietary originals.
## Birth, revision, history and source ownership

Keep ADR0003's immutable New versus Loaded birth lineage. New returns one real native image/private token-gap state at empty gap0; each New call has a distinct birth identity even when bytes/profile match. Parse acquires a distinct Loaded lineage with its initially owned image. Origin is not a filename, digest, profile, inode or a caller-settable field. Current Revision is another opaque private identity. No public origin/lineage rebase setter.

Use one private state-construction/indexing path over actual wp51.Parse, parameterized privately by the immutable lineage. Existing Parse installs Loaded; New installs New before publication. All derived operations including publishBody and Restore preserve that same lineage. Internal reparsing for native validation must not silently give a New candidate a Loaded birth. Cursor/history/preview/question/ASCII receipts remain bound to immutable revision state and actual fragments, never reassignable exported Document wrappers. Getters/export copy; stale/cross-document inputs refuse atomically; same-byte/no-op rules remain unchanged. History does not keep an unbounded ancestry chain.

Preserve `OriginalExport() ([]byte,error)`: Loaded returns copies of initially loaded bytes for the lifetime of that lineage; New returns explicit `NoLoadedOriginal` and no bytes for its entire lifetime, including after save. Export is the current native image. Initial generated bytes may be privately retained as genesis data but are not relabelled loaded original bytes. Reopening an actually saved file through Parse is a new explicit Loaded acquisition, not conversion of the still-open New lineage.

New does not automatically create global/persistent history, clear another buffer's Undelete, or claim a clear/Retrieve/new-target reset rule. Any NewHistory call remains subject to actual26 qualification and exact startup/history initialization evidence. In particular constructor success must not bypass current26 provenance/CountKnown/refusal limits. No modern undo, session clean/dirty/filename state or physical input is supplied by the constructor.

The native document owns no storage source. Only a genuinely never-sourced New buffer's later editor publication may use approved41 PrepareNewPublication/PublishNew. Those framing/absent-target APIs cannot validate semantic generation or mint a Loaded source. They retain private captured destination/opened-directory capabilities, real Close behavior and no-replace/fault/uncertainty rules. The first successful publication needs the real matching target Read/binding protocol from ADR0003, preserving the native New lineage/revision/history. A failed/mismatched anchor Read is published-but-unbound, not clean success or permission to retry source-less. Late results cannot rename/anchor/clean another revision. Once anchored, subsequent SaveAs uses the sourced guard; displayed name/last-publication receipt may change while the first anchor remains. Loaded source guards likewise never migrate silently. Never synthesize storage.Document, use a dummy loaded fixture or clear a stale guard.
