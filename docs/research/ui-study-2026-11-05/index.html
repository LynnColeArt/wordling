Wordling 5.2 · Field study · 5 November 2026

Reconstruct the experience around the document.

A visual research board from a fresh run of WordPerfect 5.1 for DOS, release 03/09/92. The gap is broader than appearance. Menus, keyboard focus, document layout, codes, file browsing and prompts form one connected application.

Twenty-six selected captures cover the editor, Help, menus and settings, formatting, Reveal Codes, wrapping, Save, Search, List Files, Look and Exit. Each card includes an observation and its interaction context. Click an image to inspect it at a larger size. Raw captures and the chronological input trace accompany the board.

What changed my assessment

The current implementation has valuable native-document and safety machinery, but the visible application still exposes only a bounded part of WordPerfect. Completing individual command handlers has not produced complete everyday workflows. We should use complete original-app journeys as the next units of implementation and review.

A practical implementation sequence

  1. Capture complete journeys. Convert this board into scripts with explicit checkpoints, including defaults, focus, cancellation, file effects and settings. Repeat the uncertain observations. Keep later-manual expectations separate from March 1992 observations.
  2. Complete the application shell. Build a shared model of screens, menus, focus and bottom-line prompts. Reuse the native document/session/storage layers. Add the original Help template and preference-backed menu visibility.
  3. Deliver one usable editing journey. Create a document, type and wrap text, move around it, apply Bold and Underline, inspect and edit codes, search, save, reopen and exit. Include the full file browser path. Finish and review every transition before calling this milestone usable.
  4. Expand against the parity inventory. Continue through page formatting, printing, tables, styles, macros, merges, graphics and the remaining commands. A usable basic editor is a milestone within parity, not completion of the mission.
  5. Gate completion on differential evidence and use. Run the same scripts in the original and Wordling. Compare character/attribute grids, cursor and focus, prompts, document bytes and file outcomes. Add independent review and a real interactive trial. PDF export should use the same qualified layout work.

Recommended immediate milestone A complete everyday editing session with faithful menus and Reveal Codes. This provides a concrete product checkpoint while retaining the full parity mission. Estimate the rest only after mapping the incomplete commands and their layout dependencies.

Presentation notes

  1. Open with the original blank screen and keyboard template. Explain the fixed cell grid and the original key vocabulary. Point out that a blank blue screen is an authentic state, but discoverability must follow the selected menu setting.
  2. Show File, Layout and the nested Justify menu. Walk through grouping, shortcut labels, borders and parent-child alignment. Show the unresolved F1 capture as a research question.
  3. Show Menu Options beside the persistent-bar editing screen. The original already supports the user's preference. Reconstruct its configuration and focus behavior rather than introducing an unexplained default.
  4. Compare normal text, wrapped text and Reveal Codes. Explain why layout, cursor motion and code presentation must be implemented together.
  5. Walk through directory request, List Files, Look and return. This is one connected file workflow. A two-column rendering alone does not complete F5.
  6. End with the proposed everyday editing milestone. Review a full journey with a usable executable, then grow the remaining parity inventory. State the outstanding work and evidence limits plainly.

Evidence and limits

The existing harness verified hashes for the master disk, boot image, QEMU executable and firmware before launching this independent offline guest. Help displays WP 5.1 03/09/92. The guest uses FreeDOS 1.4 and the established Standard Printer installation. The original profile includes printer resources dated July 1992. These details qualify the reference environment.

This is a qualitative study from one scratch guest. Early or misdirected captures remain in the raw evidence but are excluded from the selected board. The F1 nested-menu behavior remains unresolved. No graphics-mode, printer-output, startup-splash or mouse-drag fidelity claim follows from this study. The application source and preview were not changed during this exercise. The scratch session closed both documents, returned to the DOS prompt, and the guest was stopped.
