## Exact cause

editor.Session's Save branch (session.go426) calls interrupted() before filename(SaveName). interrupted (editing.go253) bypasses only already-unqualified history; qualified CountKnown=false WP40 histories proceed to document.History.InterruptGrouping. That document method intentionally refuses observed!=nil (history.go202), protecting a bounded observation from unsupported extension. The document refusal is correct for a request to qualify new history. The editor incorrectly treats that refusal as prohibiting an otherwise known ordinary Save filename transition.

Merely removing the F10 error is insufficient: successful save completion currently attempts Separate(SavedBoundary), silently keeps the prior history when that refuses, and can continue to advertise the pre-Save immediate-history permission. That would invent post-Save eligibility. Likewise a recipe workaround (typingX before F10, Restore, extra navigation, fresh Retrieve or forced clear) alters the intended accepted sequence and evades the defect.
