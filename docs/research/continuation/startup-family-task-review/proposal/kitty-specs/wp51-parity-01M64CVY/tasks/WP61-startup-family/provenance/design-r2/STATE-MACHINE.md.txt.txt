# Chosen mechanism and state machine — DESIGN ONLY

ONE isolated private supervisor process is the foreground child's actual parent
and reaper. No thread-dependent monitor, no daemon adoption or subreaper in this
first capability. Worker owns process pidfds, retained unreaped child anchor,
workspace/resource FDs, journal, streams and generic checked endpoint sockets.
The coordinator receives opaque client handles, never those raw FDs/worker tables.

## Creation, control and parent loss

1. Coordinator verifies source package origins/policies; creates fresh pinned
   workspace and O_EXCL journal; durably records component-open intent.
2. Creates two anonymous CLOEXEC bounded framed pipes; forks supervisor directly;
   coordinator retains that actual fork PID/pidfd until reap. Supervisor retains
   pidfd of original coordinator and private pipes, closes all unrelated descriptors.
   Only supervisor writes journal after this transition. There is no public pathname
   control socket, serializer-issued capability or PID-file ownership provider.
3. Supervisor sends bounded HELLO containing its observed creation/source/journal
   facts. open_session returns only after coordinator verifies actual fork identity
   and bound channel generation. Missing hello yields partial worker UNKNOWN; worker
   is forbidden to launch foreground before a separately received launch request.
4. Requests/responses use bounded length-prefixed frames, no pickle/eval. Internal
   IDs/cookies are generated by worker and kept in opaque client handles. A public
   dict, stale response, different workspace or previous channel cannot retarget them.
   stdout/stderr are streamed in bounded binary chunks, never one oversized JSON.
5. Supervisor independently polls coordinator pidfd/control EOF, monotonic clocks,
   child streams/process/RSS/source identities while consumer performs direct IO.
   Parent pidfd death OR control EOF triggers ParentLost/ControlLost and containment;
   it does not wait for an E callback to return. Child exec closes all control ends.
   A duplicated pipe cannot defeat the coordinator pidfd/deadman check.

Source reading/preparation is a supervisor state-machine job: one<=64KiB chunk then
service monitor/events before the next chunk, not a monolithic synchronous64MiB
copy. Blocking regular-file/kernel latency is still host-dependent; this is not a
hard-real-time kernel or malicious-tool sandbox. All limits/faults remain sticky.

## Session/process transitions

NEW -> OPENING -> PREPARING -> IDLE -> SPAWN_INTENT -> SPAWNED_UNBOUND -> OWNED
OWNED -> READY (only actual guarded exchange + current identity acceptance)
OWNED/READY -> EXIT_OBSERVED -> STOPPED (actual wait/reap, no original-stop meaning)
Any nonterminal -> FAULTED -> CONTAINING -> STOPPED_UNUSABLE OR CLEANUP_UNKNOWN
Any terminal -> CLOSED (cannot resume/reenter/launch NEXT)

Before foreground fork, worker fsyncs SPAWN_INTENT. It performs fork/exec itself,
retaining actual PID and exec-witness CLOEXEC pipe. Parent-result loss after possible
fork is LaunchUnknown, never0. Exec error is a recorded actual launch failure.
Missing/reused PID, executable/argv/source/socket mismatch is not OWNED. Only a
current positive kernel identity for the causally created child can mint ProcessLease.
A pidfile or post-hoc JSON assertion cannot upgrade SPAWNED_UNBOUND/UNKNOWN.
Daemonization/escaping sessions is unsupported: UNKNOWN/halt; no adoption/signals
to unproved descendants. No old fresh_start or original settings pipeline delegates.

After OWNED, coordinator receives an opaque ProcessLease; supervisor remains the
parent/reaper and owns the positive pidfd. Handoff does NOT reset timers, byte/process
counters, first fault or parent monitor. The same single policy applies across
handoff and every command/endpoint operation. Parent may do E IO while worker keeps
supervision running. A blocking/throwing consumer cannot disable worker enforcement.

Current identity is checked before protocol bytes and AFTER each readiness wait,
read/write, progress/complete response and before READY issuance. Source epochs and
kernel connected peer stay bound. I1 clocks are absolute (no reset per byte); I2
cached Identity or later outer polls are never acceptance proof. An unverifiable
fast-exit peer refuses, even with a complete expected reply. IdentityObservation is
an observation at a time, not a universal unseen-exec audit or future authority.

finish(timeout) sends NO protocol/signal; it waits boundedly for actual child exit.
It returns ExitObservation only after direct reap and observed owned-session facts.
Normal exit0 with no fault/signals permits stopped opaque resource snapshotting,
but cannot assert normalDOS/normal QMP quit/source semantics. E must separately
validate its real opaque quit receipt and all original stop/export gates.

cancel, parent loss, deadline, source/identity fault or persistence error immediately
set first fault before containment. Signal only positively anchored owned pidfds/
session members; TERM then KILL/reap boundedly. Unknown ownership is NEVER signalled
or unlinked. CleanupUnknown is terminal; it is not safe stop. Containment makes all
attached working resources UNUSABLE and forbids snapshot/export through this API.
No failed original HD may be read merely because generic cleanup returned.

## Resource transitions

SourceRequest -> VERIFIED_IMMUTABLE SourceLease (streamed exact size/hash/identity)
SourceLease --prepare no-replace--> READY WorkingLease(epoch0,owned destination FD)
READY(epochN) --mutate token+tool--> MUTATING(op-id,epochN)
MUTATING --exit0+same owned inode/bounds+immutable inputs unchanged--> READY(epochN+1)
MUTATING --ANY error/shortwrite/identity/source/persistence/overflow--> UNUSABLE
READY --attach to child--> BUSY (no copying/digesting/mutation while child active)
BUSY --normal generic exit0/no signals/fault--> DIRTY_STOPPED
DIRTY_STOPPED --checked bounded snapshot/source guards--> READY(epochN+1)+Snapshot
BUSY --containment/nonzero/unproved exit--> UNUSABLE
READY/UNUSABLE -> CLOSED; no JSON/reset/requalify transition back from UNUSABLE.

Immutable masters are never mutated. Target growth beyond64MiB, inode replacement,
link alias, outside-root retarget, source change or stale epoch fails the operation.
Atomic no-clobber preparation uses same-dir private temp+fsync+no-replace publication;
post-link failure records possible destination. No overwrite, rollback or safe-save
claim. Mutation is explicitly partial in place: on failure preserve exact bytes and
UNUSABLE state, never replace unrelated prior artifacts or refresh authority by hash.
Generic code never determines whether disk/native contents are semantically valid.

Every failed operation RAISES StartupFailure; UNUSABLE MutationResult is retained
inside its PartialOutcome/history, never returned as a normal committed success.
After first fault only copied diagnostic getters, cancellation/containment and close
are usable; no source/resource IO, new launch, mutation or retry is permitted.
ExitObservation also retains daemon_state=UNKNOWN: stopped/reaped DIRECT child and
observed session members never prove all escaped processes absent. An observed
escape faults; this is not a universal unobserved-fork audit. The opaque ProcessLease
cannot become a JSON/PID-based adopted daemon capability.

ReadyObservation proves current kernel identity at the supervisor's actual protocol
receipt/acceptance point. It is timestamped observation, not future liveness or a
client-side authority. Before EVERY subsequent action the server rechecks the live
opaque ProcessLease; delayed/replayed ready responses cannot authorize action after
exit/source change. The later E source must similarly revalidate its P lease plus
its own approved peer at every original IO boundary, not use a cached ready boolean.
