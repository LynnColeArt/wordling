## Architectural judgment

The conventional startup_family package is a genuine shared component design. Engine serves both old synchronous Attempt and new retained supervisor; artifacts serves both old small contracts and new streaming/resource custody; lifetime serves managed public operations; __init__ performs real old Attempt composition and public exports. Existing facade is amended, never falsely created. Its old fixture CLI and new closed managed-fixture CLI are concrete public consumers, with full64MiB/mutation/handoff/foreign/parent-loss/worker-death/identity-race cases specified. One engine avoids duplicating the existing full supervisor. No engine→consumer or P→E import is allowed.

Package authority plus explicit package ownership is semantically justified, beyond merely suppressing the old literal validator error. The narrow family pattern covers both actual facade and real package; it does not acquire unrelated reference controllers. New creation intent applies only to real new package/test/evidence paths. Normal lane claim must supply approved58 dependency source. Root remains planning-only; acceptance and normal CLI-owned lane→mission→target integration remain required. No early merge/overlay/placeholder/tool patch/owner reslice is accepted.

LOADING-SCOPE.md settles ordinary standalone and file-spec/alias entrypoints independent of cwd/PYTHONPATH: one canonical package/type authority, explicit source root, restricted relative package paths and verified source closure/cache origins. Same-root aliases interoperate; foreign/changed-root cache refuses rather than replacing classes/modules. This is feasible with standard importlib package loading and proper import synchronization. Actual implementation must prove initialization locking, partial-load cleanup, exact class/exception identity and early wrong-root refusal; spec_from_file_location alone does not supply these properties. These are existing frozen acceptance obligations, not claims demonstrated by this design review.
