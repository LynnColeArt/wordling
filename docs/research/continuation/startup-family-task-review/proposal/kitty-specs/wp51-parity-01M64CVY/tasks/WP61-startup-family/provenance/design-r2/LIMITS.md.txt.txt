# Frozen NEW TEST policy — no actual original/tool fit claim

These are selected engineering/test ceilings, not DOS limits or actual reference
performance evidence. Unknown QEMU/boot/firmware/mtools sizes and real emulator host
resource use remain UNKNOWN. A future authorized preflight that does not fit must
BLOCK; never silently raise these limits or inherit58 approval as a grant.

Old58 public Limits/ArtifactSpec/Attempt defaults are BYTE/behavior compatible:
8MiB byte-returning verify,16MiB copied aggregate,15s ordinary commands, readiness
<=60s still bounded by old command,1MiB/stream,16MiB output aggregate,256MiB limits,
processes8,commands16,files32, current journal/JSON/argv/cleanup and synchronous CLI.
The new policy is a DISTINCT capability, not larger arguments to old methods.

64MiB is selected from the PUBLIC declared disk extent, not an actual master stat.
128MiB allows two max-size prepared resources without whole-file memory allocation;
it does NOT establish actual boot/tool fit.256MiB workspace covers private copy temp,
versioned resources and capped diagnostics. Extra source IO is finite to permit
before/after whole-file rehash; byte count stops further IO even before time expiry.
Artifacts are opaque; large verify returns a seal, NEVER a64MiB bytes object.

Old runtime is not extended by calling old run. Managed lifetime has a genuinely
new retained supervisor/opaque lease and separate finite total clock.900s is a
chosen upper TEST policy matching the existing E declared per-leaf ceiling, NOT
proof that any original recipe fits. The closed TEST CLI uses selected2–3s lifetimes
and authored data/processes; it never waits900s or invokes original software.

Supervisor owns all active counters and counts its own plus the client's RSS and
live processes. It never lowers coordinator-global rlimits; it refuses if aggregate
sampling exceeds its policy. Worker/child rlimits and FD limits are intrinsic.
Count/time/byte budget is shared through preparation, launch, handoff, IO and finish;
no quota reset at a callback or new client handle. Once background monitoring starts,
coordinator silence is NOT authorization to stop monitoring. Fixed file/kernel
syscall latency and OS scheduling remain host-dependent: sampled overshoot can be
observed after it occurs; no hard-real-time or hostile-process sandbox promise.

Large/managed opt-in must be frozen in a future complete source/test/consumer packet.
No original resource metadata/stat/read, VM, grant, guard or ledger is authorized by
this design; later E still requires separate reviewed source/prelaunch+NEW ROOT grant.
