# Independent WP61 working-lease successor gap

**Confirmed contract defect; proposed narrow amendment below.** This is an independent contract-gap review, not a code verdict or permission to implement a silent deviation. Author implementation source was not inspected or executed. Historical frozen artifacts remain unchanged. ROOT must ratify/canonicalize the amendment through normal governance and refresh current analysis as required before treating it as binding.

Audience: ROOT and WP61 implementer. The exact frozen API requires Session.mutate(WorkingLease,MutationSpec)→MutationResult and Session.snapshot(WorkingLease)→Snapshot (API.md48–50). WorkingLease is opaque/nonconstructible, with stale epochs refused (53–59). MutationResult and Snapshot contain only scalar/fact observations and no returned lease (101–104). Yet STATE-MACHINE.md85 advances a successful mutation to READY(epochN+1), and89 advances DIRTY_STOPPED snapshot to READY(epochN+1). Canonical WP61 lines77,83,101 require these exact APIs, advancing epochs and stale-old-handle refusal. No other operation returns a lease for an existing working resource. A caller cannot lawfully perform snapshot/launch/second mutation with the newly committed epoch. This cannot be repaired by changing a frozen input wrapper in place, reconstructing a handle from facts, accepting stale handles or silently changing mutate's return type.

I missed this concrete composition defect in the earlier design/task analyses. The defect concerns the proposed new API only; it is not evidence of a defect in approved P58 or a code finding against the unfinished author source.

Recommendation: keep both operation signatures and existing observation fields; add an explicit opaque successor slot to the two new result types. MutationResult.successor is WorkingLease on COMMITTED and None on UNUSABLE diagnostics. Snapshot.successor is WorkingLease on successful snapshot. Clarify the facts-only wording narrowly: scalar observation fields remain copied immutable facts; these two result types may additionally carry an issuer-created opaque lease, which cannot be minted by reconstructing the result or its observations.

A READY read-only snapshot must not manufacture a new version: preserve epoch and return the identical current input lease. A DIRTY_STOPPED snapshot is the already-specified guarded requalification: advance once and return a new current lease. Returning successor on both snapshot paths gives callers one usable shape without making snapshot one-shot or adding lookup/reacquire APIs. All operations remain subject to existing session phase, one-child/command/time/byte limits, sticky first-fault and source/identity guards. No new launch/reentry/resume permission is introduced.

See addendum.md for proposed normative text and conformance.md for positive/failure tests. All5 exact frozen design contract hashes and canonical task/source references are bound in bindings.json. No historical packet resealed; no canonical/source/lifecycle/primary writes, tests, private tool/resource access, original VM/grant or new task IDs. Full M1 remains open; M2/PDF gated.
