## Smallest useful source amendment

Factor the existing fresh_start implementation into **resource preparation** and **supervised transport startup**, with fresh_start retained as the compatibility wrapper. These are PUBLIC documented boundaries, with real tests and a single implementation; not a copied driver, patched module globals, fake original-resource provider or an alternate decoder.

1. **Explicit resource description and validation.** Public preparation takes immutable profile/installed-file manifest paths, expected profile digest, master paths, required tool/firmware identities, fresh work/runtime endpoints, and asset names/paths. It validates the actual files and exact purpose/domain before copy/injection. The production wrapper selects its current fixed original-reference inputs and independently retains the ROOT-profile equality gate. A harmless test-only description supplies project-authored bytes, local fake-tool identities and a synthetic manifest; the SAME preparation algorithm can validate/copy/roundtrip these, without opening original profile/master/resources. It cannot be returned or asserted as an original-qualified descriptor. No test path accepts `resources_valid=true` or bypasses hashing.
2. **One bounded command-execution contract for EVERY command in that preparation/start path**, including settings_snapshot; do not add a callback solely around QEMU and leave mdir/mcopy unbounded. Its production implementation records immutable argv/env/cwd/tool identity, invocation/start/end monotonic timestamps, bounded separate stdout/stderr, exit/signal/deadline/overflow, owned process identity, and cleanup outcome. It streams bounded data while running; `capture_output` then slice is insufficient. Public result/error types retain partial telemetry even when the command starts then raises. No shell execution, inherited group kill or foreign process signals. No success on overflow/nonzero/timeout/partial write. Tests invoke this REAL bounded implementation with harmless OS programs; a stubbed success result is not the required proof.
3. **Start observation BEFORE launching, not only after subprocess.run returns.** A public launch operation publishes a planned-attempt event before resource commands, command-spawn evidence when the launcher actually exists, and QEMU-daemon owned-identity evidence as soon as it is positively available. Its result/exception carries the attempt journal even if startup/observer/QMP fails. Once a launch syscall could have happened, `launch_state=UNKNOWN` is mandatory until positive NOT_STARTED or OWNED_RUNNING/STOPPED proof; lack of a return value/pidfile is never zero guests. Distinguish the daemonizing launcher from the later owned daemon: killing/reaping the launcher group alone does not prove QEMU stopped. Pidfile delayed/missing/reused, mismatched executable/kernel argv/disks/startticks or socket all refuse normal success. A bounded owned observation deadline returns an unsafe/unknown report rather than inventing no-start or stop.
4. **Owned QMP readiness remains injected publicly AFTER launch observation.** Startup waits through the approved owner-checking factory, with no foreign greeting/capabilities. Preserve its actual source-backed startup criterion by default; do not add document semantic assertions to this transport work. Normal-stop receipts, positive PID/startticks/socket stop and stopped extraction belong to the current consumer's approved stop/accounting API. Failures must retain the launch journal so that API can contain only positively owned processes and report unknown ownership honestly.

These are contract requirements, not a proposed callable API frozen before implementation review. A concrete implementation can expose preparation+start functions or an equivalent explicit transport object. It must make validation, execution, launch identity and failure telemetry separately testable through supported PUBLIC calls. An arbitrary caller-supplied executor/observer alone does not prove safety: the default real supervisor and its orchestration must be exercised, and external consumer cannot turn synthetic receipts into original qualification.

**guest.py need not change for the minimal path.** Reuse its unchanged pure arguments builder for actual originals and preserve the real argv. Harmless OS fixtures belong to explicitly synthetic launch specifications driving the same supervised transport, not substitution of the actual original QEMU argv in a supposedly original run. If implementation discovers a need for explicit endpoint arguments in guest.arguments rather than its imported runtime globals, that is an additional honest source-owned amendment to guest.py, with compatibility tests. It is pre-mission tracked code with no current task scope owner, NOT WP13-owned. Declare that file explicitly; do not silently patch it. No second guest.start engine is required.

## Required review proof before any future grant

Offline proof must use harmless regular files/local processes/socket endpoints only and exercise PUBLIC preparation/start/default bounded executor, not private monkeypatches or a substitute successful supervisor. Include: actual small valid synthetic preparation/roundtrip; profile/tool/resource mismatch and mutation after validation; mdir/mcopy analogues with nonzero, overflow, hang, partial output; no-clobber/symlink/work reuse; actual process starts then raises/observer error; launcher exits while child remains; delayed/missing pidfile, PID reuse and foreign socket; owned process/group cleanup and reap; bounded stdout/stderr independent of time; QMP cannot run before ownership; exact failure journal survives exceptions.
