## Why the route is sound

A predicted recalled field need not already have a photograph. Experimental
hypotheses can be frozen before observing them. Here every accepted prediction
must describe the SAME intact Retrieve filename function in its exact ordered
history, with full25×80 character/attribute planes and CRTC state. A positive
match authorizes only ONE F1, followed by observation. It does not authorize
character entry, Enter, a menu recovery loop or a guessed normal exit.

REF516/92 printed55–56/PDF72–73 documents F1 backing out of a status request,
while distinguishing ordinary editing/Undelete, Help and macro definition.
Printed554–555/PDF571–572 identifies Retrieve and separately describes error
return. I visually inspected private printed55 and555; no manual images/text
are deliverables. The actual paired13 prompt/draft/F1-return captures corroborate
the specific March program's direct Retrieve cancellation. Combining this
applicable command semantics with a positively identified full Retrieve request
supports the proposed conditional cancel without pretending its history-sensitive
contents are already qualified. If cancel returns anything unexpected, the whole
plan halts before another behavioral key. Unknown permits only owned containment,
not automatic F1 or successful normal-DOS qualification.

The H-empty/prior-Retrieve/prior-Save table is finite, mechanistic and explicitly
prospective. It is sound to test such a table and discover none matches. It is
not sound to implement optional cue/cursor suffixes, arbitrary recalled text,
substring recognition or a table widened after a first fault. The proposed
exclusion of typing in the second field is essential: Save/Exit replacement rules
at printed195/PDF212 and566/PDF583 do not establish Retrieve typing behavior.

## Material mode condition: establish it after clear

**Do not assume Typeover survives document clear.** Printed695/PDF712 documents
Ins toggling, the visible Typeover status indicator, and returning to Insert by
exiting the current document. The paired43 clear witnesses are Insert-context
blank frames; their body/status and coarse helper predicate are not proof of a
Typeover post-clear state. POS uppercase is Caps Lock (printed57), not Typeover.

This is a mandatory source-implementation condition, not a demand for a prior
novel-history photograph:

- Freeze separately the mode before first Retrieve, the source-based predicted
  mode after the precise clear route, and the actual mode required before second
  Retrieve. A visible filename request hides that underlying mode; its contents
  cannot establish it.
- An exact source-backed predicted main-mode frame may safely gate Shift-F10
  AFTER the actual full body/status/attributes/CRTC/context matches. It remains
  a prediction until that match; disagreement is a counted whole-plan failure,
  not permission to repair the expectation or toggle experimentally.
- If a Typeover SECOND-field pair is claimed, the separately reviewed plan needs
  an explicit **source-known mode establishment/reset** route after clear when
  required: for example, only from positively matched Insert main state, the
  documented known Ins transition, then a strictly matched Typeover main state
  before Shift-F10. This is a predeclared conditional transition within the same
  counted attempt, not a discovery-time recovery key or extra calibration.
  The actual raw/mode/Ins source closure must be supplied before implementation
  can rely on it; the62-source packet alone does not qualify that route.
- Alternatively retain Typeover only as PRE-clear history exposure, with an
  explicitly Insert second field after clear. Such results must be labelled that

The design's step4 already allows a source-backed frozen reset rather than

## Exact source and transport checks

The actual approved `Probe.type` delegates its input unchanged to `qmp.type`.
Independent AST literal inspection establishes that the source-rendered
`C:\\OUT\\` prefix is **seven input bytes**, hex433a5c4f55545c: one ASCII5C
backslash at each separator. QMP maps each one-character backslash to the
`backslash` qcode. There is no helper unescape, deduplication or reduction layer.
Python/JSON/Markdown escape notation is not a second literal keypress. The future
plan must bind semantic DOS path, AST-decoded input bytes/length, installed path,
frame payload and actual trace separately and consistently; names remain unfrozen
in this design. Do not transport doubled physical separators merely because a
rendering displays two escape characters.
