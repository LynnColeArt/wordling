## Narrow implementation

The protected failure region has no poll(), wait() or communicate() that consumes child ownership. Completion after pipe EOF uses Linux waitid(P_PID, captured_pid, WEXITED|WNOHANG|WNOWAIT). Before nonzero group signals, the wrapper verifies that the Popen child remains unreaped and actual PGID==SID==that captured start_new_session PID. This is a kernel child/group/session proof, not a production /proc scan, arbitrary PID lookup or test-only assertion. An unproven/already-consumed pin produces CleanupOwnershipLost without signalling. Tests explicitly verify no signal on a mismatched group observation.

Failure cleanup sends TERM only to that private group, allows up to1s grace, then sends KILL to the SAME still-pinned group regardless of the leader's exit status. An exited leader cannot suppress escalation for an ignoring descendant. Inherited output pipes then receive a bounded EOF drain (<=1s/1MiB discarded); parent reap is bounded to1s. Already-gone groups are tolerated, and inability to establish EOF/reap is surfaced as CleanupFailure rather than a successful no-orphan claim. No stronger claim is made for a process deliberately escaping the private group or external host reaping interference; the wrapper never signals a foreign/unproven group.

The immediate child remains unreaped until final group signalling/drain completes. Success-only reap happens outside the protected region. Selector construction/read/close faults and pipe-EOF-before-wait-timeout retain the ownership pin and enter cleanup. Output/diagnostic/input/native/source budgets and the public CLI/signatures remain unchanged. The failure cleanup has an explicit additional bounded3s envelope (grace1 + EOF1 + reap1); this is not a guarantee of instantaneous kernel scheduling or historical DOS latency. Child SIGKILL delivery can briefly precede Z state, so proof uses a bounded positive wait/reap, not a single instantaneous /proc-state guess.

No Go/native/parser/helper/admission/interpreter/document/storage/editor/TUI/VM code changed. No production subreaper, cgroup, process-tree scan, group search or broader kill exists. Only the positively captured private PGID is signalled. Test-only Linux subreaper instrumentation lets the isolated test process waitpid its own known adopted descendants, verify start ticks/argv/exe/PGID/session, then prove group disappearance after exact reap. It does not modify the production process model.
