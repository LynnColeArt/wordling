## Source-based creation-only route

The proposed four independent leaves each start original WP from the same fingerprinted fresh guest/profile and create one short ASCII source, not Go New/native input. Use the already observed plain `abc` setup from approved23 as carried by approved43; preserve exact selected original metadata/resource/settings scope. No printer-port configuration or print command is needed. Settings (including FastSave choice) must be explicit and source-bound; don't inherit unseen defaults from a prior guest.

1. Capture original startup/New and its actual mode/body/title/status; type `abc` in that qualified context. Source43 captures original creation/first ASCII and first Save. No CtrlN/new shortcut is invented.
2. F10, capture **unnamed initial Save prompt**, type a separately declared new scratch PRE path, capture its exact typed draft, then Enter only from that positively qualified filename state. Capture named Save completion and CRT/body/title/source state. PRE remains a distinct guest file for stopped export; do not overwrite it.
3. Use the explicitly observed Home3/Up then Right-to-gap1 primitive, with before/after full captures. Keep Insert if positively observed; for the Typeover condition toggle Insert and verify the actual Typeover state **after PRE Save and movement**. No F7 clear occurs before this operation, so no claim that pre-clear Typeover persists through clear. Source23 observes ASCII gap1 and mode toggling; source13 records hardware cursor/gap contexts. Record actual mode, don't toggle blindly.
4. Capture the complete pre-Enter state, send ONE Enter, immediately capture full text4000B VGA/raw attrs/PNG/PPM/CRT and positive guest/process identity. This is the discriminating operation, not a macro, a composed text transport `\n` assertion, or a native API call. Competing native outcomes include insertion versus replacement/advance/other behavior; keep every outcome literal and do not infer code/metadata from the keyboard event alone.
5. **Only after an independently justified exact post-Enter normal-document rule accepts it**, F10 and obtain a distinct POST file via **named Save-As**, with actual prefilled-name prompt, full replacement draft, completion/title/body and cursor captured before every next key. No Retrieve, clear, second Retrieve, recalled Retrieve field, in-guest copy, same-name overwrite or pre-stop extraction occurs.
6. Finish through independently qualified normal exit questions/DOS, then positively owned QMP stop. Export both PRE and POST only from the stopped owned guest, plus all approved public captures/trace/provenance. Release actual shared resources before offline native audit. Failure gets QMP-only owned stop and diagnostic public captures; no guessed cancel/recovery/exit keys or private failed-HD extraction.

This isolates Enter as the only document-content operation between the two saved snapshots. **POST is Enter+explicit Save-As mediated native output, not an unsaved-memory dump or pure Enter-only prefix delta.** Full metadata comparison must retain Save/name effects honestly. Source43 actually retains distinct G43TEXT/R43TEXT/A43TEXT exports across saved-name transitions; source13 shows named prefill/caret and character-first replacement. Those are sources for designing Save field rules, not a general caller-literal matcher or new-state permission.

## Exactly what is known and what blocks step5

Approved43 `native_genesis.save` captures first prompt/draft/completion and later named Save prompt/draft/completion. Paired originals show first `Document to be saved:` empty, later `Document to be saved: C:\OUT\R43TEXT`. Approved13 CMD51-069 pairs show prefilled filename/caret movement and character-first replacement, including hardware cursor captures. Approved23 mode recipe records plain ASCII gap1/typeover then insert. These component sources make a no-Retrieve route plausible; there is no need to depend on outstanding secondRetrieve typing behavior.

They are not sufficient to label this proposal launch-ready:

- Approved14's alpha/Enter/beta normal/Reveal endpoints do not capture Enter's immediate before/after CRT or typeover behavior; there are no hardware cursor.json files in either L1-HR run. Its selected formatting/line-height/resource setup differs from plain New, so don't infer screen rows or printed position from font/CPI/LPI labels.
- A new split multiline frame/body/status/cursor/mode/title must be distinguished from centred modal, other document, pending prompt or unexpected rendering **before F10**. Existing generic `main`/Doc1 substring helpers are insufficient. Freezing the newly encountered unknown frame as its own expected fixture would launder it into authority.
- Initial empty and later prefilled Save are different contexts. New scratch filename literals, before/after field caret/body/source lineage and full25LF rows need an independently reviewed semantic/source-bound field rule. Don't feed new literals through old observed fixture IDs, optional-cue normalizers or private expected-record APIs. New first-Retrieve rules do not qualify Save fields.
- Normal exit of the resulting multiline state needs the same positive full-context discipline. Actual source-known low-level capture/process/stop helpers are infrastructure only, not normal-state or native-operation permission.

Therefore no extra keys or guest are authorized to discover these unknowns opportunistically. A separately reviewed acquisition protocol with a source-justified complete rule, or an explicitly reviewed human-gated acquisition boundary, must resolve these prerequisites; otherwise stop BEFORE PRELAUNCH. This report supplies neither a live matcher nor a human approval/grant. New acquisition/research task or contract amendment is a separate root decision after independent design review.
