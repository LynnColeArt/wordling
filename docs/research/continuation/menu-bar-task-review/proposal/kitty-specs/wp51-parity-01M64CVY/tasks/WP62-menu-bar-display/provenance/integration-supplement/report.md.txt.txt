# Integration-trap supplement to sealed post60 reconnaissance

The original3-member report seal68ced92229e26e952f145affe85de89a731abcd2f50bba7aade8abcbaa50ce3f is unchanged. This separately sealed supplement records the final requested integration checks. Recommendation remains strictly the evidenced bar-cell display subset, not full menu modality/caret parity. No code or canonical action is performed.

- **Row0 is occupied.** Current H View places product branding on row0 and document/error on row1. A bar overlay must not insert a row, move the document/error/caret, erase pending/reconciliation notices or change state-derived rows. On close restore the SAME prior visible frame/heading; this is an explicit Linux presentation difference from original off-row0 blank. Do not claim all-screen VGA equality from a row0-only test.
- **Real startup blank versus no document.** Approved Runtime.Open calls editor.New, which constructs document.New with the historical profile and a fresh history. This genuine source-less new buffer is not a nil Document/zero Model. Existing H60 inspectionEligible requires Reveal and is inappropriate to copy as menu eligibility. A later design must bind an actual captured startup/new-document state without creating a fake Session/Doc, beginning IO, advancing genesis/first-save publication or exposing native capabilities. Zero/uninitialized/noDoc models must refuse or show explicit unavailable state rather than manufacture the captured blank-document context.
- **First-save and pending modes.** Idle initial new-document state is distinct from first-save filename/observe/prepare/publish/read-back/retry and unsettled or detached IO. An overlay cannot hide a required question, steal its answer, consume a ticket, rename or mark a revision saved. Those contexts should stay excluded absent evidence, preserving current visible frame and IO ownership. Merely checking `Pending == nil` is insufficient to establish all tickets/deferred/reconciliation states are idle.
- **Frozen DISPLAY OFF and macro lifetime.** Select the chosen frozen visible frame before any new bar state. Do not draw a live bar over suppressed frozen output or leak current source/diagnostics through State. Start/run/read/deferred/stop macro transitions and inherited H37/60 frozen contracts must remain authoritative. Excluding all active/pending/suppressed macro states is the narrow initial option; even an exclusion must not consume claimUI authority.
- **Prompts, notices, virtual frames and stale models.** Name/Delete/Undelete/Repeat/history/selection/reconciliation/error/Doc2 contexts lack this menu oracle. Do not reuse the exact rendering toggle to imply a generic modal transition. A stale copied Model must not acquire menu visibility or affect the authentic current UI token. Source/revision/first-save/history fields remain observations, not alternate menu authority.
- **Input identity and unexpected keys.** Alt+= is one delivered press identity, not Escape followed by equals, Alt text stripped into ordinary insertion or a keyboard capability request. Distinguish release/repeat/paste/alternate fields. With a displayed bar, unsupported arrows/letters/Enter/help/cancel keys must not silently edit native text or fake submenu dispatch. A safe explicit refusal may be a declared bounded limitation; original semantics of those keys are not established by the two-toggle recipe. Do not accidentally map menu Alt+= to the separate existing Esc Repeat prefix.
- **Dimensions and styles.** Original cell evidence is exactly80×25; current application clips both width and total rows and adds style resets. At80×25 match the full row0 text and all80 attributes. Zero/one/tiny heights or width<80 cannot produce that full bar; define a safe clipped/unavailable host result without original parity claim. Resize while shown must remain nonmutating and style-contained. Width>80 does not authorize stretching an original80-column row, new wrapping or new menu geometry. Menu71/74/47 are logical menu attributes; copying Reveal-active47 mechanics would wrongly conflate UI selection with a native code cursor. Palette/RGB/font/hardware caret remain unqualified.

A later author should resolve these integration choices in a narrow design and acceptance contract, using actual public Model+production PTY layers with honest observability. No missing original semantics are solved by this supplement, and generic P61 transport by itself is not original-run authority.
