## Source authentication and pre-copy limits are implementable

The proposed function belongs to package document, so its new file can capture the existing private revisionState once, compare expected.state with that same capture, use the existing validated absolute gap array, and call the immutable image's bounded Bytes operation. It does not need an amendment to document.go, Kind, identify, Cursor, admission, history or wp51. The existing public Revision is an opaque pointer identity: equal bytes from a separate Parse do not authenticate a source. Existing Element already carries TokenIndex/Kind/Span/Text. A small copied inspection value can therefore expose labels without creating a semantic token kind or mutation capability.

Capturing once before inspecting fields is essential. Do not repeatedly dereference the caller-replaceable exported wrapper. The contract protects serialized wrapper replacement and old immutable captures; it does not authorize unsynchronized concurrent mutation of a Go wrapper. Returned values remain caller copies and must never be accepted back as permission.

The complete span for start..start+count is available from the captured gaps before calling Token or Image.Bytes. Overflow-safe count<=total-start and count<=4096, followed by raw span<=256 KiB, permit atomic refusal before copying an oversized payload window. A whole variable owner may be 65,539 bytes, which fits the stated envelope but must never be partially copied/classified to fit. One bounded window copy is feasible. Current emitted labels are at most six bytes, so 4096 elements imply at most 24,576 text bytes: the 32 KiB text ceiling can be proved as an upper bound as well as checked, rather than inventing an unreachable overflow fixture. Element-array and constant-string allocation remain finite. Count-zero, true EOF and a truncated window are distinct, representable results.

Use existing failure categories for invalid document/revision/window/budget cases. Unknown Opaque+empty Text must remain an explicit unsupported owner; successful inspection does not change its semantic Kind. No raw caller Token, file name, image hash, original screenshot or fabricated revision may become source authority. The draft's stale/crosssource/wrapper/alias/old-capture and complete-owner/inner-byte/budget mutants are appropriate implementation obligations, not tests performed by this design review.

## Actual future consumer is reachable without permission widening

Checked actual G47 source: Read completion calls Document.Parse and acquires CursorAt(0), retains opaque content, and enters Editing independently of mutation admission. Session.Document returns a wrapper copy over immutable native state. Snapshot.NativeRevision is the document identity; integer Session.Revision has another role. AltF3 can toggle Reveal without admitting opaque edits.

Checked actual H52 panes and View. panes currently calls Session.Present before the label switch; opaque owners cause early error and empty strings. Therefore adding only a downstream label switch would remain unreachable. View already retains an upper unsupported notice, can append a separate lower string when Reveal is on, and disables the document caret on error. A separately implemented fallback can consume the new E projection on the same captured Document/NativeRevision while preserving that error and noCaret. H needs no raw decoder, second document, CursorAt jump or semantic admission change.

The draft correctly requires actual loaded14 -> Read -> Document.Parse -> public Model -> AltF3 and production executable/PTY proof later. An exported E library entry is the production inspection boundary for this prerequisite; it must remain usable by that real consumer, not be replaced with a fixture/test lookup. E alone must not claim a visible feature. Future H implementation/review must actually wire and prove the consumer before claiming a lower-pane improvement.

The fallback must remain restricted to explicitly qualified native Editing/Reveal states. Existing successful ASCII/Bold Present behavior and active styles stay intact. Block/history overlays, macro DISPLAY OFF's frozen strings/style/error/source, pending/name/modal/stale-source/fork/resize behavior cannot be replaced by live underlying native content. Preserve the original upper error and no document caret; any bounded placeholder for unknown owners is a host diagnostic, not an invented WP code label. TrueEOF/truncation, unsupported prefix-owner retention and no new dirty/revision/gap/source/IO effects are explicit future acceptance obligations. No active47 or physical geometry for HR/HP is licensed here.
