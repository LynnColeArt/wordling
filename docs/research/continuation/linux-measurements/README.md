# WP19 bounded Linux measurements

The actual approved read-only application was measured on Linux. Small original
fixtures have sub-millisecond model/IO calls here, while synthetic PTY prompt
responses cluster around one16–17ms interval. These are separate boundaries;
parser speed does not establish editor latency or physical input-to-photon.
No original/Wordling response-time ratio or full-editor performance is claimed.
Every budget below is a proposal for review, not an owner-accepted requirement.

`run-02` is the final measurement method. `run-01` remains unchanged with a
qualified RSS instrumentation defect, described below. Each run retains12 exact
fixtures,31 measured samples plus3 separate warmups per available phase, all
errors/skips/outliers,12 fresh application processes, wire bytes and source/native
fingerprints. `design.json` was written before measurements. Quantiles use nearest
rank without trimming; p99 of31 samples and p95/p99 of11 warm processes are the
observed maximum, not credible estimates of rare long-tail probability.

## Timing and resource boundaries

The Go child acquires the input and prepares a real temporary source outside
phase timers. It times native parse, rooted read+native parse, document
construction, complete token traversal, no-edit export, Runtime open/close,
Runtime+model retrieve+close, reducer Reveal, Model.Update AltF3,100x25 Model.View
and actual no-edit new-name publication separately. Publication includes model
F10/text/Enter, real Observe and Save commands and bound completions. Every
published copy and original source is byte-compared outside its phase timer.
A fresh Runtime is used per retrieve; the sole model owns each IO chain and its
operation IDs. No intent is replayed from a forked session. Reducer inspection
never executes an IO intent. Successful publication uses34 unique names, under
the actual1024-operation Runtime safety cap. Construction may duplicate native
buffers; allocation deltas are retained rather than guessed from input length.

Go monotonic time.Now/time.Since brackets each callback. MemStats counters are
read outside that interval; process-global TotalAlloc/Mallocs deltas include
runtime activity during the callback. They are allocations, not peak memory.
No forced GC occurs inside a timed callback. A separate empty-callback calibration
uses the same collector; its raw31+3 samples remain in collector-calibration.json
and are not subtracted from measurements. Raw warmup timing and allocation
spikes remain visible. There are no hidden best-of-N or outlier removals.

Per-fixture child `/proc/self/status` RSS after forced GC includes the measurement
harness, raw inputs and retained layer values, not a standalone application.
Self ru_maxrss is taken before final source-audit rereads; GNU time measures the
complete child including final invariant audit and shutdown. Thus the16MiB+1
refusal has about22MiB post-GC resident memory yet about55MiB complete-child
peak, largely from fixture acquisition/final byte audits, despite near-zero
parser allocation. It is not evidence that a size refusal allocates55MiB.

Run01 showed self/wait4 highwater near28MiB while `/proc` exec-image VmHWM was
about7MiB for plain input: Python fork/preexec resident history polluted that
boundary. Its raw results are retained and excluded from final peak proposals.
Run02 launches through GNU time, whose fresh child starts from its small exec
image. The wrapper wait4 value still includes Python fork history and is labelled
accordingly; actual application peak comes from GNU time's child report.
Self/proc/external peak differences are preserved, including final audit costs.
No lower number is substituted into a raw record.

Actual `cmd/wordling` runs in12 new synthetic100x25 Linux PTYs with
TERM=xterm-256color and LANG=C.UTF-8. Timing starts before process launch, or
before writing exact documented protocol bytes, and ends when the expected cue
is read from the master fd. Raw output and per-send offsets/hex are retained.
Startup includes wrapper/process launch, initialization and first renderer
output; key timings include transport/decoder/model/IO/frame scheduling and
Python/select observation overhead. They exclude physical key travel, terminal
emulator drawing, display scanout and photons. Capability responses are injected,
not physical terminal qualification. Final exit is actual F7→No→Yes, code0 with
termios restored and source/publication exact. Runtime drains its real IO.

The first process is labelled first-observed; the other11 are OS-warm starts.
Builds and previous processes warm caches. True cold filesystem/page-cache
startup is unmeasured; this investigation never labels first-observed as cold.
Original WP14 capture settling and scripted input sleeps are not response-time
samples. Original timing comparison, physical delivery, physical-to-paint and
another terminal/profile remain explicitly unqualified.
