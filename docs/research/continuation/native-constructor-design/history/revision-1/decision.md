Do not author E yet. Its blockers are not the absence of an empty file:43 has two real324-byte empty originals and six first-ASCII originals. ## Profile supply, licensing and config ownership

Distinguish three things: the historical application's private resource inputs; a qualified **serialization data profile**; and the actual resources needed for Linux layout/printing. Equal hashes or a typed profile ID do not grant permission to bundle original SET/PRS/DRS/EXE or assert those resources exist on a user machine.

Preferred first path is an explicitly selected, lawfully supplied historical cached profile, if its qualification provider can validate the exact supported SET/PRS/resource observations and deliver an immutable typed serialization snapshot. No runtime source-loading requirement is hidden inside document.New: profile qualification/acquisition belongs to its own resource boundary and its lawful resource provisioning must be explicit. Existing storage.Document is a native-document source observation and cannot masquerade as this profile. E must not smuggle a SET parser into document.Parse or accept an arbitrary prefix blob as a profile.

A profile that is independently generated and redistributable is a separate option. Current evidence does not establish descriptor/hash/metrics/default generation for it, so it is blocked rather than populated with copied proprietary payloads, zero caches or an invented Courier substitute. A future review could authorize packaging individually explained, lawfully redistributable metadata for a closed profile; that is a specific provenance/licensing decision, not implied by this architecture. Until such an artifact/provider exists, do not promise a standalone zero-resource constructor.

Proposed public shape remains `New(NewConfig) (*Document,error)` with explicit supported qualified profile selection, zero config refused. Exact config fields must await the held-field/provider contract. It must expose no native prefix, arbitrary offsets/maps, caller-owned mutable resource slices, raw cached-state setters or runtime IO capabilities. Any accepted provider wrapper is captured by private immutable profile value/snapshot; whole-wrapper replacement after New, changes to input config, getters and resource Close cannot retarget a published native document. Close controls the provider's actual acquisition lifetime; it cannot retroactively modify already-owned typed values. Do not conflate native metadata identity with filesystem authority. A profile cache may be shared only as private immutable data with explicit lifetime/memory accounting.
