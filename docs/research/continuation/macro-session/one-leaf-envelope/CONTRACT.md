The original three positional arguments, intrinsic policies, public Result/observation dataclasses, existing Session method signatures, old eight-fixture and managed fifteen-fixture rosters remain. None retains previous enforcement. New immutable observations and policy share the actual canonical package/facade identity; wrong roots/cache hashes cannot share authority. ## Selected policy and exact scope

SharedEnvelopePolicy requires origin/end, finite nonnegative monotonic numbers with 0 < end-origin <=960s. open_session rejects wrong exact classes, future origins and expired selections before owned workspace creation, checks again after source/path work, and never extends the captured end. Its remaining integer fields are positive tightening ceilings: source_io<=4GiB, prepared_bytes<=128MiB, commands<=16, output_bytes<=16MiB, processes<=8, rss_bytes<=256MiB, fds<=64, control_messages<=4096, control_wire_bytes<=64MiB, polls<=100000, journal_events<=512, journal_bytes<=1MiB, endpoint_bytes<=64MiB. Intrinsic StreamPolicy/ManagedPolicy ceilings still intersect these selections; none is raised. The endpoint total is a separate new opt-in count of brokered P channel bytes, not an E-protocol counter.

The earlier origin precedes this worker's setup and all its calls. The same end applies during source transfer, preparation, mutation, the one original, selected channel operations, passive finish, stopped snapshot, idle monitoring and provisional/commit publication. Existing total/session/startup/readiness/operation limits still apply at their actual boundaries. OWNED without open_endpoint has no new global readiness timeout or caller READY assertion. Exact CheckedChannel readiness/I1/I2 remain required when selected.

One retained Session/root/generation has one original maximum and terminal closure, no reset/reopen/refund/continuation method. Preparation mutators are charged external invocations before that original. Separate independent open_session contexts remain available to old callers. Policy DATA does not identify a logical E plan: P cannot recognize separately supplied policies/workspaces as the same logical leaf. No CLI workflow opens another Session to continue its leaf. Future E's retained issuer must enforce its one logical leaf/protocol/publication budget; a new independent Session is not same-leaf proof or original permission.

## Actual measurements and conservative publication

Usage uses the SAME live supervisor and committed RPC. It verifies current process identity while active, live root/resource descriptors and immutable source path/stamps, and actual bound actor census. Source hashes originate from checked capture; ordinary writes/retargets change the checked stamps. Measurement does not read a stale client snapshot or rehash whole tools on every getter. Stopped usage retains history and exposes no fabricated live identity/READY.

Each observation is a measured prefix: session_id, real operation sequence/time, origin/end/elapsed, charged external attempts, exact brokered source_io, prepared_bytes, max_chunk, current/peak sampled RSS/processes, polls/output, journal events/bytes/durability, control messages/wire, P endpoint TX/RX, current/peak aggregate FDs and per-(pid,startticks) actor FD rows, original state/current identity, and outstanding response/loss fields. Helper state/count are None (not applicable before WP64), not invented successful helpers. Unknown live actor measurement refuses MeasurementUnknown; it never supplies zero credit.

A census includes coordinator, actual worker and the causal active child/session members. PID birth ticks are checked before/after; the worker's own transient directory-list FD is excluded after it closes. Linux can deny a zombie fd directory: ONLY a same-birth kernel Z proof allows the known closed-descriptor count; an unreadable live actor refuses. The actual actor FD/RSS/process peaks are simultaneous sampled facts, not cumulative/refundable credits. A conservative ten-FD/transient-child reservation and process slot check precede fork; continuous sampling enforces actual later usage. Global parent limits are not lowered.

Usage source_io counts actual mediated reads PLUS working-copy writes; default historical SessionOutcome source_io remains its old read count. Opt-in outcomes additionally expose transfer_io, so those two outcome counters reconcile the combined usage total. Reads and writes reserve remaining brokered extent before effects, then charge actual bytes. Preparation/phase/epoch changes do not reset counters. Opaque tool/device/mmap/all-syscall IO is not measured or certified by this counter. Usage checks themselves perform no whole resource transfer; their real protocol traffic and journal intent do consume budget.

The control ledger includes HELLO, each actual request, provisional response and atomic commit, including length headers. Before operation effects it reserves <=65540 provisional bytes +256 commit bytes and two response frames. Usage reports the already measured prefix plus that still-outstanding bound; it does not claim to count its own future response. Actual progress consumes the bound, complete matching commit reconciles unused slack, and loss permanently spends the remaining reservation with sticky first fault. There is no public credit setter. A small selected limit can conservatively refuse before a smaller eventual response would have fit. Diagnostic cleanup may become UNKNOWN when no coherent bounded report can be delivered; it does not refund or mint authority.

Approved I3 framing remains: generation/sequence/SHA-matching atomic commit publishes a provisional response. Full supervision, selected absolute clocks, source/resource and current identity checks continue around waits/writes and commit. Partial OR fully queued provisional usage without commit is never returned. A queued-frame fault closes the generation rather than concatenating an error frame. Post-commit future faults deny future operations; the earlier measurement is not a promise of future liveness. Fault journaling and bounded containment can continue after the selected action deadline to record truthful cleanup, without granting another action.

## Limits and executable callers

The new closed envelope-fixture roster is positive, expired, absolute-progress, source-io, prepared, commands, output, fd, process, rss, wire, observation, response-loss and external-peer. It accepts no arbitrary tool/path/argv/profile/grant. Positives use real public capture/preparation/mutation/successor, actual original lease/usage/current/passive finish/stopped snapshot in one Session. Worker-loss TEST cleanup holds a positively verified created-child pidfd; that fixture cleanup is reported separately from the source's truthful UNKNOWN outcome.

All tools/files/Unix peers are authored disposable TEST fixtures. No original/private resource was inspected or run. Sampling and scheduler latency/overshoot are explicit; this is not a hostile sandbox, hard real-time guarantee, unseen-exec/escaped-daemon proof or all-kernel-IO limiter. Passive identity_at_exit_unproved/daemon_state UNKNOWN stay facts. Launch/control/source/causal faults remain sticky and cannot support future stopped-seal authority. Full M1 remains open; M2/PDF remains gated.
