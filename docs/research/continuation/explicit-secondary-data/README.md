# Explicit Secondary DATA qualification

This maintainer workflow exercises the production `internal/merge/explicit`
package through real native Parse → Secondary View → source-bound DATA admission
→ explicit Value getters. It replaces no original format and creates no native
result. Generic Secondary `Supported`/`Admit` remains blocked.

Run from the actual implementation checkout containing this work package:

```sh
python scripts/reference/explicit_secondary_data.py audit --report /tmp/explicit-data-report.json
python scripts/reference/explicit_secondary_data.py inspect --input SECOND.WP5 --role Secondary --report /tmp/explicit-data-inspection.json
```

The report parent must already exist. The target must have a .json suffix and
be new or an existing genuine workflow report; native inputs, pinned source
roster aliases, symlinks, nonregular targets and unrelated existing files refuse.
Path and actual inode identity are checked again before publication under trusted
local directory assumptions, not a hostile-owner CAS guarantee.
Reports are bounded diagnostics, not input
authority or Wordling document sidecars. `audit` checks all30 original images in
ten paired run contexts from207/208/209/216/217. It first obtains actual DATA
handles, then compares field bytes/spans to the unchanged WP53 independent
observations. It records Primary/Result no-edit custody without executing them.
`inspect` accepts only the Secondary DATA role and does not select values by
path, digest or fixture name. A fresh source with Clara instead of Alice is a
supported synthetic structural example, not a new original result observation.

`Data` and `Value` are immutable by-value handles over private captured native
ownership. Admission copies the whole caller View once and authenticates the
expected opaque Source. Equal-byte independent parsing is foreign. Explicit
empty requires its own EF delimiter; a missing ordinal returns typed
`ExplicitFieldMissing` plus an invalid Value. Raw counts and unaddressed tails
remain uninterpreted. Returned bytes and native provenance are defensive copies.
Repeated immutable API calls are not lifetime-metered; each call is bounded and
one qualification enumeration returns at most the admitted body’s content bytes.

The six exact opaque D4 owners are finite whole-owner predicates, not formatter
algorithms or permission to strip metadata. The two broader WP53 C8/page3–4
cohorts remain refused. Every command/token/record/field/finding site and all body
bytes must be covered. Native generic blockers/findings and original exports
remain unchanged after DATA admission.

The launcher imports only the public `bounded` function from an exact immutable
staged copy of approved WP53. It calls no old Session/authority loader/private
supervisor and changes no globals. It owns a new source manifest and reports
actual GoFiles, Go/assembly/header sources, local/standard package closure,
compiler archives, toolchain/compiler/binary hashes, arguments, working directory,
input digest, raw output base64, statuses and elapsed time. The compiled binary
and staged helper are temporary and deleted after the invocation; their observed
hashes remain in the report. VCS metadata is diagnostic, not source authority.

A successful report replaces its destination only after all checks finish. On a
caught failure, the prior successful report survives; a uniquely named sibling
`*.failed-*.json` can preserve a clearly failed attempt. Inherited public bounded
exceptions do not expose partial output or final child status: those fields are
explicitly unavailable/unknown, never reconstructed or called zero. Numeric
signals require the inherited helper’s actual unreaped-child/PGID/SID proof.

See POLICY.md for finite Linux budgets, report.md for measured results and raw
red limitations, inherited-pins.json for all59 source/fixture pins and221 old
members, and source-manifest.json for the actual compiled composition. This is
four local packages, not the old16-file/three-package observer composition.
No merge evaluator, PAGE effect, native writer, ordinary Merge UI, original
launch, private resource access, PDF or parent parity acceptance follows.
