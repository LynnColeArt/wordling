## A — source-less absent-target publication

Add these proposed public storage seams, with private fields on the new type:

```go
Directory.PrepareNewPublication(target *Destination, data []byte, id PublicationID) (*NewPublication, error)
Directory.PublishNew(p *NewPublication, expectedID PublicationID) (Outcome, error)
```

`NewPublication` retains the exact Directory instance, its observed absent Destination, a private owned wp51.Image, ID, length and SHA256. It has copied value inspection analogous to Publication.ID/Size/SHA256 and no exported mutable image or bytes. Preparation checks nonnil directory/target, exact target-directory binding, nonempty valid observation, target absent, nonzero ID fields, input bounds and wp51.Parse. Parse supplies framing/type admission and owned copying; WPM is refused. Caller bytes may be reused after return and must not be modified during preparation. Preparation rechecks destination; PublishNew rechecks it and exact prepared ID. A zero/fabricated/cross-directory handle refuses before IO.

`NewPublication` is a separate type from existing sourced `Publication`; nil source is never an alternate meaning of PreparePublication or Publish. Existing PreparePublication still requires a real acquired source from the same Directory, including all prepare/publish/pre-link freshness checks. Existing Save's current source and cross-directory behavior is preserved exactly rather than accidentally tightened by refactoring. Macro.Image wrapper fix34 remains untouched in meaning. NewPublication establishes **framing and publication safety only**; storage cannot infer semantic edit permission or whether arbitrary bytes originated in a loaded editor buffer. The editor routing invariant below is required and tested. Do not claim the new type cryptographically proves native genesis.

Internally factor the current `publish(doc,target,data,hash)` into one private no-replace transaction supplied with an explicitly constructed, nonnil guard carrying a private kind: loaded-source guard or source-less guard. Unknown/zero guard refuses. Loaded guards retain their real Document and execute checkSource at all existing boundaries; source-less guards explicitly have no source check and can be created only by the NewPublication path. Do not implement `if doc != nil { checkSource(doc) }` as general optional validation. Both paths retain destination validation, exclusive candidate creation/pinning, bounded write/close, candidate identity+byte verification, pre-link checks, no-replace link, post-link verification, owned cleanup, final verification and pin-close reporting. This is a narrow common transaction extraction, not a second filesystem engine.

Preserve existing Outcome/Failure semantics. Error after possible link/cleanup/pin-close can leave a destination or candidate: carry DestinationMayExist/Candidate and exact error; never unlink an observed destination as rollback. No automatic retry after uncertainty; re-observe under a new operation only after explicit reconciliation. No fsync/durability, global cancellation, atomic source freshness, hostile same-directory exclusion, generic overwrite or compare-and-swap guarantee is added. Existing conservative no-replace failure classification may report possible existence even on a failed link. Keep that conservative meaning.

Acceptance for A includes caller-byte independence, framing/WPM/zero/cross-directory/ID negatives; source mutation at every original guard boundary; unchanged old Save/Publication/Macro tests; real late destination creation; short write/close/read/link/cleanup/pin failures; candidate substitution/residue; complete no-replace output identity; and exact before/after loaded-source behavior. Use existing filesystem fault seams and real rooted-file tests. No constructor or guest experiment is needed for A's framing/transaction contract; it must not imply semantic new-document acceptance.

## E — native birth, constructor and revision identity

Add a private immutable lineage object captured by every revisionState. Public inspection is an opaque comparable `Origin` with an inspectable `Loaded` or `New` kind; zero means invalid. Each successful Parse creates a distinct Loaded lineage; each successful constructor creates a distinct New lineage. Equal bytes do not give equal origin or Revision. Origin identity is in-memory only, never a native field or sidecar.

Keep Revision as private revisionState identity. Cursor, selection, edit/deletion receipts, history and previews remain bound to the exact revision and required history state, not just origin/hash/session counter. Every admitted native mutation creates a fresh state, retaining its lineage. Refusals preserve all existing state. Same-byte operations keep their existing reviewed revision semantics. Any internal Parse used to validate a derived candidate must transfer the original immutable lineage before publishing the new state; it must not silently relabel a constructed document Loaded. All paths, including Restore and later field expansion, must use one reviewed derivation routine or equivalently prove the same invariant. No mutable public origin setter or rebase is provided.

For Loaded lineage, OriginalExport keeps its current meaning: copies the initially loaded native image across later edits and saves. For New lineage, OriginalExport returns an explicit `NoLoadedOriginal` refusal and no bytes **for its entire lifetime, including after first save**. Export returns the current constructed native image. Initial constructed bytes may be retained privately in the lineage for structural-difference checks; they are not described as loaded original bytes. Saving does not mutate birth identity or reset history/revision. Reopening a saved file with Parse creates a new Loaded lineage as an explicit new acquisition, distinct from the still-open constructed lineage.

Proposed constructor is `document.New(config NewConfig) (*Document,error)`, producing the same private immutable state/gap/token authority. NewConfig contains only typed settings with independently qualified native encodings; its exact fields/default values await D. Choose an explicit qualified genesis profile; no zero-config fallback silently guesses printer, locale, setup or metadata. Public callers cannot inject a prefix template, arbitrary native image, mutable map or field-offset table as a constructor configuration. Construct native fields directly from the researched schema and literal original encodings; validate with wp51.Parse and applicable mutation admission. No embedded unexplained fixture prefix, live external conversion, synthesized storage.Document or native Wordling marker is allowed.

D must establish whether an empty original state has a valid saveable native representation, which defaults are serialized versus session/resource state, exact packet/index/link/length/counter/flag rules, initial formatting state, first text save, re-save and Retrieve transitions. If empty save is not established, the constructor remains blocked; do not manufacture a placeholder parsed file or lazy dummy source. Time- or resource-dependent fields need explicit typed values and researched encoding, not hidden wall-clock/host defaults. Literal fixed bytes are acceptable only where individually explained by the original field contract. D research can require a schema-specific constructor detail refinement before E is authored; this architecture does not invent those fields.

B separately establishes which original-resaved/deleted/slack families admit changed bodies; C extends mutation admission only for those proved relationships. Constructor approval cannot bypass the original re-save editability cliff by normalizing everything to324 bytes. E initially supports only researched construction plus inherited admitted operations; it adds no hard returns, new Bold creation, C0 interpretation or formatter by implication.

## F/G — first-save, names and storage anchors

Keep four concepts separate in private editor state: immutable native birth Origin; retained acquired storage source guard (possibly absent only before a genuinely New buffer first binds); displayed document name; and the last-publication receipt with its document Revision, destination and bytes identity. The displayed name and last-publication destination do not identify or replace the retained source guard. A session/buffer identity, current opaque Revision, history identity and monotonic operation/sequence counters bind pending work. Existing uint64 PublicationID fields are caller correlation, not replacement document identity or storage authorization. The pending immutable request retains the exact native revision/Origin and payload hash/length; worker results must match operation, buffer, kind and request revision. Snapshot/Intent copies must not expose writable aliases of candidate bytes, public Document wrappers, configs or slices. Reuse actual approved27/36 contracts, not the proposed26 checkpoint as accepted API.

New session construction must explicitly receive/create a valid New document through E and install it via a checked immutable snapshot; do not make existing editor.New callers silently fabricate one. Choose an explicit new-start option/factory while retaining approved read-only startup compatibility until G deliberately selects it. The reducer executes no filesystem IO. Both views render the same real document. Do not assume document clear/retrieve resets history, or that two screens/new targets inherit saved-target macro behavior; consume approved contracts or refuse those unqualified transitions.

A **never-published New buffer with no acquired source anchor** may emit the distinct new-publication intent. A Loaded buffer must always carry a real acquired anchor and use existing sourced publication. A New buffer that has acquired its first saved anchor thereafter also uses the sourced route: being born New does not authorize permanent source-check bypass. Dropping an anchor after stale/error/cancel is not a transition back to unsourced. These are private tagged session states, not tests of `Source()==nil` alone.

First naming/empty-save/cancel/dirty/prompt/exit transitions come from D and corrected13 evidence; architecture supplies safety, not guessed WP semantics. A filename draft is not a committed document name. For the first genuinely source-less New publication only, on verified matching PublishNew success, retain its exact positive receipt and perform a real storage.Read of that target, matching directory/name and full returned final publication identity/hash/length/bytes to the prepared candidate before installing the acquired anchor. This Read must be a separately typed follow-up of the same logical save, not a Retrieve that replaces the native document or resets cursor/history. After binding, current native Revision remains unchanged; the anchor owns an independent copied storage snapshot. The selected name/saved revision may become authoritative only when the whole matching binding succeeds, and only in the originally authorized prompt branch.

A positive publication followed by failed/mismatching anchor acquisition is **published but unbound**, not absent or rolled back. Preserve receipt/name-on-disk and error; do not mark a clean successful exit or permit another source-less publication from that buffer. Reconciliation may acquire a matching saved file under an explicit new operation, or require supported recovery; it never silently retries/replaces. An uncertain publication is similarly unresolved. This explicit host-safety refusal is not claimed original application behavior.

If typing, buffer switch, cancel/detach or a later operation invalidates the request, its eventual output remains a detached filesystem receipt. It cannot rename, clean, anchor, replace history or authorize exit for the current revision; a deliberate reconciliation step is needed. In particular, late successful first saves do not silently turn a changed New buffer into either clean or a fresh source-less retry. Duplicate worker dispatch/result must not perform/adopt effects twice. Keep existing Runtime.Close worker draining and retained receipt discipline.

After that first binding, preserve approved17's retained-source contract for both Loaded buffers and already-bound New buffers. A later successful sourced Save As may update the displayed name to the successful draft and record a distinct last-publication observation; it **does not Read/rebind or replace the source guard**. Loaded buffers keep their original acquired source; New buffers keep the first positively acquired anchor. This choice preserves b479983 session.go WriteSnapshot behavior and the explicit TestGivenSeparatePinnedDirectoriesWhenPublishThenTargetIdentityAndSourceRemain regression. A new Retrieve is an explicit separate acquisition, not an implicit consequence of saving. No later Save As guard-migration work is included in A–H; any proposed migration requires separately scoped original research, compatibility decision and independent review before authoring.

Consequently, mutation of the retained original source (or the New buffer's first anchor) must still cause StaleSource on a later sourced operation after Save As. Mutation of a previously published different output does not by itself make that output the source guard; it matters when the actual next destination observation or an explicitly requested acquisition involves that file. Cross-directory no-edit publication through approved Save retains the original guard's Directory while the displayed name and last-publication observation may refer to another pinned Directory. Preserve PreparePublication's existing same-Directory constraint for edited candidates: an unsupported cross-directory candidate route refuses rather than synthesizing/rebinding a source. Destination checks remain mandatory and no earlier output receipt authorizes overwrite.

No-edit same-file no-op is available only where actual sourced Save identifies the destination as the retained source inode with exact matching bytes and the approved session branch permits it. A displayed Save As name pointing at a different existing output does not turn that output into the retained source or a same-file no-op; existing replacement remains unsupported. Further edited same-name save likewise remains unsupported existing-file replacement; only separately supported sourced Save As to an absent destination proceeds. OriginalExport never substitutes for current payload/last saved bytes. Source-stale/overwrite refusal cannot be escaped by selecting the source-less route.

## Alternatives, consequences and retained work

Rejected: nil-source overload (weakens existing callers); dummy loaded fixture/storage source (fabricates identity); separate new-file transaction (duplicates security/fault ownership); exporting mutable document state (breaks cursor/history receipts); returning genesis bytes from OriginalExport (lies about loaded input); reparsing current document after save to change origin (discards native revision/history identity); clearing source on stale-save error (bypasses guards); template normalization (loses unrelated native relationships).

Accepted cost: two public publication types with one transaction, private lineage memory, an additional acquired-anchor read for the first never-sourced New publication only and a published-but-unbound safety state. Later sourced Save As retains its existing guard and needs no implicit acquisition. These costs make caller responsibility explicit and keep the early storage package independent of later native research. This is an architectural choice, not evidence that the original uses these internal concepts.

All38 obligations,91 groups,36 workbook lessons and nested leaves remain. Existing-file overwrite/backup/recovery and durability, full native/companion formats, full search/macros/merges, return/formatting/layout/printing, original resources/languages/graphics/historical DOS and physical input remain M1. New absent-target creation does not solve any of them wholesale. No full requirement/scenario closure, acceptance, merge, M2 or PDF is authorized by this decision.

No source, primary planning, task/lifecycle state, guest or evidence commit was changed. The report and manifest are temporary architecture handoffs only. WP40's now approved recipe already includes immediate post-Restore history reinspection; no amendment is proposed here.

## Revision 3 — prepared-request capture ownership clarification

This is a narrow architecture delta awaiting independent design/task review. The sealed independent investigation `wordling-publication-alias-independent` reproduced three P2 failures on unchanged approved storage70e02f7: sequential caller replacement of the acquired Document wrapper bypasses the prepared original guard, replacement of Destination retargets the name, and replacement of Directory redirects physical output into another pinned root when a hardlink is created before acquisition. Baseline tests still pass; the independent public-API race overlay fails all three real assertions. Neither a data race nor caller mutation during synchronous Prepare/Save is involved. Prior two architecture review cycles remain historically intact; cycle2 did not assess this later discovery. No source repair or product approval is implied. Exact repro/review hashes and prior design archive are in the manifest revision receipt.

**Correction to A:** preserve original loaded-source/destination guard *meaning* at every existing boundary by capturing their accepted referents, rather than retaining reassignable public wrappers. Explicitly repair the existing Publication ownership class together with introducing NewPublication, within the existing storage component. Preserve current public signatures. A private immutable opened-directory capability owns the actual rooted handles, filesystem adapter and acquired FileID; a public Directory value refers to that capability rather than being the authority whose mutable field values a prepared request follows. Equivalent private capture is acceptable only if it proves the same independent lifetime/identity properties. Shallow-copying Document/Destination while retaining their public *Directory pointer is insufficient.

At PreparePublication, capture the accepted source name/full Identity/native image and its stable opened-directory capability, the exact accepted target name/existence/Identity observation and its stable capability, and the receiver's stable capability. Each captured observation is private and immutable; caller's later zero/same-directory-other/cross-directory whole-wrapper assignment cannot rewrite it. Candidate bytes/image and PublicationID retain independent owned state as before. Revalidate the captured original source at prepare, Publish and pre-link boundaries. If that original changes, return the existing stale/refusal outcome before publication regardless of replacement caller wrappers. Capture does not freeze filesystem state or replace freshness checks. Target late creation still refuses through the original absent-name checks and no-replace link.

Choose **rebound receiver refusal**: Publish/PublishNew must compare the receiver's current stable capability to the capability captured by the request *before any filesystem IO*. Nil/zero/closed or a receiver replaced with a different capability explicitly refuses, with no output or candidate in either substituted or original root. Public wrapper pointer equality is not capability equality. A copied Directory value that still designates the same legitimate open capability remains usable under the existing resource lifetime; do not invent a fresh authority merely from its new wrapper address. Capture the request's private state once during the synchronous call and run all subsequent guard/destination/transaction work through that captured capability. Concurrent caller mutation during API calls remains outside the guarantee; sequential between-call wrapper replacement is covered. PublicationID is correlation, not capability authorization.

Resource lifetime remains real: capture neither duplicates/reopens handles nor keeps a closed directory secretly usable. Directory copies alias the same private resource lifetime. Close on a wrapper closes the capability it currently designates; an earlier copied wrapper still designating the original can close that original after another wrapper is reassigned. Once that capability is closed, prepared requests and aliases must fail safely rather than resurrect it, use a new root or leak/use a stale descriptor. Preserve legitimate resource Close behavior and typed error reporting; a second Close need not become a newly promised idempotent success. Do not close the wrong capability or silently transfer descriptor ownership on whole-wrapper replacement. Runtime.Close still drains workers before closing its acquired capability. No per-publication duplicated directory resource or new reference-counting subsystem is required.

NewPublication captures its exact absent target observation and stable receiver capability with the same invariants, naturally without a source observation. Source-less guard cannot mean weaker destination/root ownership. Its immutable private observation must not follow caller *Destination or *Directory assignment. Old synchronous Save continues to accept its already supported cross-directory source/target arrangement, perform its original guard/no-op/no-replace behavior and preserve Close semantics; do not narrow it to PreparePublication's same-directory policy. The bounded structural change to acquired Directory/Document/Destination wrappers may be shared internally where necessary, but no general API rewrite, broad replacement feature or new semantic permission is selected. Existing stored source observations should use stable acquired capabilities so shared checks cannot follow a rebound public root.

Acceptance must first reproduce the sealed independent public overlay failures on exact unmodified70e02f7 (real exit1 with no races) and then pass equivalent permanent public-API regressions on the repair. Include source wrapper zero/other/same/cross-root replacements plus changed retained original; destination wrapper zero/other absent/existing/cross-root replacements plus late original-target creation; directory receiver zero/rebound variants with the pre-acquisition hardlink control and actual physical output assertions. For rebound receiver require refusal before candidate creation/IO; no redirected output. Test a legitimate copied same-capability receiver, original-root rename, Close via original/copy/rebound wrappers, already-closed capability, wrong capability and actual final cleanup/descriptor lifetime. For destination wrapper replacement, retained prepared target or explicit safe refusal is permitted; never substituted output. Preserve old source-stale/candidate/write/close/link/cleanup/pin/final-verification/uncertain tests, old no-edit Save cross-directory behavior and34 immutable Macro.Image semantics. Verify actual inherited editor/TUI consumers without new task/lane dependencies; later product use of NewPublication remains F/G, not claimed by A. Original directory capability/resource state stays private, zero wrappers refuse safely, and equal path/FileID alone is not enough to fabricate a captured capability.

This clarification changes the authoring scope of WP41/T121–123 coherently within storage: fix accepted prepared source/destination/root capture and add the source-less type through the same transaction. It does not change WP42/WP43 research content, the A–H lane direction, New/Loaded origin or OriginalExport semantics, first New-anchor binding, later sourced SaveAs retained-source contract, native genesis research prerequisites, no-replace/outcome limits or all38/91/fullM1 obligations.
