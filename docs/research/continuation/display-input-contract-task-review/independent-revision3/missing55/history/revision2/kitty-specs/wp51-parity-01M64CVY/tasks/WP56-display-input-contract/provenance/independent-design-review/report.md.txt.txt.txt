## Why this is beyond49

Approved49 contract already supplies source-bound live font scalars, complete
outer formatting operands, actual original settings, seven empirical/documentary
rules and full PRN/source verification. Its `text_flow_contract.py:117–134`
extracts six fields from the single actual live owner and records units/spans.
Its CLI validates that observational result; it does not qualify a reference
configuration as applicable to a current E document/cursor or distinguish selected
status-unit setup from observed unit suffixes. Rebuilding those existing tables
would be corroboration, not the new deliverable.

The proposed delta is useful: for each dimension, classify native stored literal,
explicit operand, selected setting in an exact original phase, UI observation,
and qualified/unresolved applicability to a separately identified context. This
makes a correct partial-input handoff possible while every runtime ruler/status
tuple remains unresolved. An actual public classifier/query must demonstrate
that delta; merely appending `runtime_display_ready:false` to49 JSON is inadequate.

The design correctly preserves native-owned initial/body state as a possibility.
SDK WP11/PDF24 describes packet3 initial codes. Its absence from the selected43
minimal324/332-byte family does not mean zero margins/tabs or prove that all
initial state lives solely in SET. Actual43 `native_genesis.py` saves first,
then calls `settings_after`; later menu observations cannot retroactively prove
first-save configuration. Existing native literals in that first file remain
known irrespective of that phase gap.

## Manual and applicability boundary

Private REF51 and SDK PDF/text hashes match the supplied pins. Using the PDF
skill I visually inspected REF printed121/PDF138 and SDK WP11/PDF24; temporary
page images were removed. Only hashes/locators/paraphrases are retained.

- REF121–122/PDF138–139 distinguishes resource-derived printed character/space
  widths from display pitch used to represent certain absolute-distance codes.
  Document scope/saving and Automatic/manual selection are documented. This is
  not a complete effective resource/format/quantization algorithm.
- SDK WP11/PDF24 identifies packet6 width/pitch/resolution and manual-pitch flag;
  bit0 explicitly addresses WPWIN. Raw width120 is not CPI, raw pitch0 is not
  proven DOS100%, and those fields do not supply a universal screen mapping.
  The known raw flag/field facts should still be reported literally.
- REF699/PDF716 separates general units from status units and identifies paper-
  relative Ln/Pos, with a4.2 exception. An observed inch suffix is an observation,
  not proof that a persistent setup selection was captured. Neither a native WPU
  field nor a typed inch-suffixed argument establishes either global selection.

The design is right to keep status-unit setup unresolved:14 did not explicitly
select/capture that setup choice. The same evidence rule must apply separately
to GENERAL entry/display-unit selection. A displayed menu unit or explicit input
suffix can be known in its own source/phase without being promoted to a recovered
global setting. This is a source-implementation condition, not a reason to erase
those observations or reject the design.

Printer/SET/font file fingerprints establish presence/identity, not semantic
availability or a metrics provider. General fixed/Auto line-height contexts43/14
must stay separate. Counter02 and related native cache changes remain literal
protocol observations; no printing-alone cause, writer promotion or repair rule
follows. NativeProfile, NewBirth, Parse, CheckMutation and equal exported bytes
are not independent display-configuration identity.

## Required conditions for later task/source acceptance

1. **Demonstrate the new qualifier, not just49 output.** Public positives must
   classify actual13/14/43 source phases per dimension. A correctly bound later
   captured setting can be reported as such; moving that same setting into the
   earlier first-save phase must change applicability/refusal while native
   literal facts stay intact. Differentiate source forgery from a supported but
   insufficient input. Rehashing caller metadata cannot turn either into proof.
2. **Keep the unit dimensions distinct.** Preserve explicit argument units,
   observed menu units, selected general entry/display setup, observed UI status
   suffix, and selected status setup as different evidence roles. Missing setup
   selection remains unresolved; no WPU/inch suffix or copied default substitutes.
3. **Keep literal knowledge separate from applicability.** A validly framed
   changed scalar can remain a known literal value/unit from its own immutable
   image. A forged claim that it is the original captured resource/profile must
   fail. Do not turn an unsupported profile claim into a false native-invalid or
   all-literals-unknown result, and do not use120/hash/name as an admission rule.
   Hash-bound reference custody is legitimate; hash-to-runtime-geometry is not.
4. **Use genuine owners and immutable identities.** Any consumed field must bind
   actual production-reader spans/index/pool references to the exact image and
   source. If existing Document/Revision/Birth/Cursor are queried, capture their
   actual immutable state, not replaceable exported wrapper addresses. Reference
   experiment identity is separate from current configuration revision. Cross-
   image/phase/profile/cursor, stale aliases, zero/nil and partial failures need
   real public-boundary controls. No new renderer-facing runtime API is implied.
5. **Make the new negatives semantic.** Required source/phase/unit/default/status/
   resource promotions must fail after all local hashes are recomputed, not only
   because a checksum became stale. Include non-fixture native values and the
   old/new operand distinction; no first matching field/ruler text, canned
   Pg1/Ln1/Pos1 or gap/10 shortcut. Reusing49's owner/PRN tests alone does not
   establish this new qualification contract.
6. **Retain bounded read-only scope and topology.** Declare finite input/output/
   time/RSS limits and atomic failure behavior for the actual public CLI and
   dependency calls. No product writes, New/history operations, hidden provider,
   resource bytes, guest or Go source-admission change. Future E research depends
   on approved native/manual/original/49 authority; H52 is consumer context only,
   not E import/prerequisite. Current54/55 work is not a shortcut to authority.

These conditions are consistent with the design's stated acceptance, rather than
new implementation scope. Its correct terminal state can be known literal and
reference-setting classifications plus explicit missing effective derivation,
with `runtime_display_ready:false`. A full font engine is not required merely to
report a known scalar; a scalar is not enough to grant an effective display API.

**Recommendation:** proceed to bounded E selected-display-input/source-phase
qualification contract authoring, preserving the above acceptance distinctions.
No current task/ID/schema implementation, runtime ruler/status consumer, original
acquisition or native/UI/writer permission is approved here. Existing53/54/55 and
geometry work remain separate. All38 obligations/91groups/36lessons/nested/fullM1,
physical metrics/resource/graphics and M2 gates remain open.
