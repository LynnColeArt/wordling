## A — source-less absent-target publication

Add these proposed public storage seams, with private fields on the new type:

```go
Directory.PrepareNewPublication(target *Destination, data []byte, id PublicationID) (*NewPublication, error)
Directory.PublishNew(p *NewPublication, expectedID PublicationID) (Outcome, error)
```

`NewPublication` retains the exact Directory instance, its observed absent Destination, a private owned wp51.Image, ID, length and SHA256. It has copied value inspection analogous to Publication.ID/Size/SHA256 and no exported mutable image or bytes. Preparation checks nonnil directory/target, exact target-directory binding, nonempty valid observation, target absent, nonzero ID fields, input bounds and wp51.Parse. Parse supplies framing/type admission and owned copying; WPM is refused. Caller bytes may be reused after return and must not be modified during preparation. Preparation rechecks destination; PublishNew rechecks it and exact prepared ID. A zero/fabricated/cross-directory handle refuses before IO.

`NewPublication` is a separate type from existing sourced `Publication`; nil source is never an alternate meaning of PreparePublication or Publish. Existing PreparePublication still requires a real acquired source from the same Directory, including all prepare/publish/pre-link freshness checks. Existing Save's current source and cross-directory behavior is preserved exactly rather than accidentally tightened by refactoring. Macro.Image wrapper fix34 remains untouched in meaning. NewPublication establishes **framing and publication safety only**; storage cannot infer semantic edit permission or whether arbitrary bytes originated in a loaded editor buffer. The editor routing invariant below is required and tested. Do not claim the new type cryptographically proves native genesis.

Internally factor the current `publish(doc,target,data,hash)` into one private no-replace transaction supplied with an explicitly constructed, nonnil guard carrying a private kind: loaded-source guard or source-less guard. Unknown/zero guard refuses. Loaded guards retain their real Document and execute checkSource at all existing boundaries; source-less guards explicitly have no source check and can be created only by the NewPublication path. Do not implement `if doc != nil { checkSource(doc) }` as general optional validation. Both paths retain destination validation, exclusive candidate creation/pinning, bounded write/close, candidate identity+byte verification, pre-link checks, no-replace link, post-link verification, owned cleanup, final verification and pin-close reporting. This is a narrow common transaction extraction, not a second filesystem engine.

Preserve existing Outcome/Failure semantics. Error after possible link/cleanup/pin-close can leave a destination or candidate: carry DestinationMayExist/Candidate and exact error; never unlink an observed destination as rollback. No automatic retry after uncertainty; re-observe under a new operation only after explicit reconciliation. No fsync/durability, global cancellation, atomic source freshness, hostile same-directory exclusion, generic overwrite or compare-and-swap guarantee is added. Existing conservative no-replace failure classification may report possible existence even on a failed link. Keep that conservative meaning.

Acceptance for A includes caller-byte independence, framing/WPM/zero/cross-directory/ID negatives; source mutation at every original guard boundary; unchanged old Save/Publication/Macro tests; real late destination creation; short write/close/read/link/cleanup/pin failures; candidate substitution/residue; complete no-replace output identity; and exact before/after loaded-source behavior. Use existing filesystem fault seams and real rooted-file tests. No constructor or guest experiment is needed for A's framing/transaction contract; it must not imply semantic new-document acceptance.

## E — native birth, constructor and revision identity

Add a private immutable lineage object captured by every revisionState. Public inspection is an opaque comparable `Origin` with an inspectable `Loaded` or `New` kind; zero means invalid. Each successful Parse creates a distinct Loaded lineage; each successful constructor creates a distinct New lineage. Equal bytes do not give equal origin or Revision. Origin identity is in-memory only, never a native field or sidecar.

Keep Revision as private revisionState identity. Cursor, selection, edit/deletion receipts, history and previews remain bound to the exact revision and required history state, not just origin/hash/session counter. Every admitted native mutation creates a fresh state, retaining its lineage. Refusals preserve all existing state. Same-byte operations keep their existing reviewed revision semantics. Any internal Parse used to validate a derived candidate must transfer the original immutable lineage before publishing the new state; it must not silently relabel a constructed document Loaded. All paths, including Restore and later field expansion, must use one reviewed derivation routine or equivalently prove the same invariant. No mutable public origin setter or rebase is provided.

For Loaded lineage, OriginalExport keeps its current meaning: copies the initially loaded native image across later edits and saves. For New lineage, OriginalExport returns an explicit `NoLoadedOriginal` refusal and no bytes **for its entire lifetime, including after first save**. Export returns the current constructed native image. Initial constructed bytes may be retained privately in the lineage for structural-difference checks; they are not described as loaded original bytes. Saving does not mutate birth identity or reset history/revision. Reopening a saved file with Parse creates a new Loaded lineage as an explicit new acquisition, distinct from the still-open constructed lineage.

Proposed constructor is `document.New(config NewConfig) (*Document,error)`, producing the same private immutable state/gap/token authority. NewConfig contains only typed settings with independently qualified native encodings; its exact fields/default values await D. Choose an explicit qualified genesis profile; no zero-config fallback silently guesses printer, locale, setup or metadata. Public callers cannot inject a prefix template, arbitrary native image, mutable map or field-offset table as a constructor configuration. Construct native fields directly from the researched schema and literal original encodings; validate with wp51.Parse and applicable mutation admission. No embedded unexplained fixture prefix, live external conversion, synthesized storage.Document or native Wordling marker is allowed.

D must establish whether an empty original state has a valid saveable native representation, which defaults are serialized versus session/resource state, exact packet/index/link/length/counter/flag rules, initial formatting state, first text save, re-save and Retrieve transitions. If empty save is not established, the constructor remains blocked; do not manufacture a placeholder parsed file or lazy dummy source. Time- or resource-dependent fields need explicit typed values and researched encoding, not hidden wall-clock/host defaults. Literal fixed bytes are acceptable only where individually explained by the original field contract. D research can require a schema-specific constructor detail refinement before E is authored; this architecture does not invent those fields.

B separately establishes which original-resaved/deleted/slack families admit changed bodies; C extends mutation admission only for those proved relationships. Constructor approval cannot bypass the original re-save editability cliff by normalizing everything to324 bytes. E initially supports only researched construction plus inherited admitted operations; it adds no hard returns, new Bold creation, C0 interpretation or formatter by implication.

## F/G — first-save, names and storage anchors

Keep three concepts separate in private editor state: immutable native birth Origin; currently acquired storage source anchor (possibly absent); and last positively saved document Revision/name/bytes identity. A session/buffer identity, current opaque Revision, history identity and monotonic operation/sequence counters bind pending work. Existing uint64 PublicationID fields are caller correlation, not replacement document identity or storage authorization. The pending immutable request retains the exact native revision/Origin and payload hash/length; worker results must match operation, buffer, kind and request revision. Snapshot/Intent copies must not expose writable aliases of candidate bytes, public Document wrappers, configs or slices. Reuse actual approved27/36 contracts, not the proposed26 checkpoint as accepted API.

New session construction must explicitly receive/create a valid New document through E and install it via a checked immutable snapshot; do not make existing editor.New callers silently fabricate one. Choose an explicit new-start option/factory while retaining approved read-only startup compatibility until G deliberately selects it. The reducer executes no filesystem IO. Both views render the same real document. Do not assume document clear/retrieve resets history, or that two screens/new targets inherit saved-target macro behavior; consume approved contracts or refuse those unqualified transitions.

A **never-published New buffer with no acquired source anchor** may emit the distinct new-publication intent. A Loaded buffer must always carry a real acquired anchor and use existing sourced publication. A New buffer that has acquired its first saved anchor thereafter also uses the sourced route: being born New does not authorize permanent source-check bypass. Dropping an anchor after stale/error/cancel is not a transition back to unsourced. These are private tagged session states, not tests of `Source()==nil` alone.

First naming/empty-save/cancel/dirty/prompt/exit transitions come from D and corrected13 evidence; architecture supplies safety, not guessed WP semantics. A filename draft is not a committed document name. On verified matching PublishNew success, retain its exact positive receipt and perform a real storage.Read of that target, matching directory/name and full returned final publication identity/hash/length/bytes to the prepared candidate before installing the acquired anchor. This Read must be a separately typed follow-up of the same logical save, not a Retrieve that replaces the native document or resets cursor/history. After binding, current native Revision remains unchanged; the anchor owns an independent copied storage snapshot. The selected name/saved revision may become authoritative only when the whole matching binding succeeds, and only in the originally authorized prompt branch.

A positive publication followed by failed/mismatching anchor acquisition is **published but unbound**, not absent or rolled back. Preserve receipt/name-on-disk and error; do not mark a clean successful exit or permit another source-less publication from that buffer. Reconciliation may acquire a matching saved file under an explicit new operation, or require supported recovery; it never silently retries/replaces. An uncertain publication is similarly unresolved. This explicit host-safety refusal is not claimed original application behavior.

If typing, buffer switch, cancel/detach or a later operation invalidates the request, its eventual output remains a detached filesystem receipt. It cannot rename, clean, anchor, replace history or authorize exit for the current revision; a deliberate reconciliation step is needed. In particular, late successful first saves do not silently turn a changed New buffer into either clean or a fresh source-less retry. Duplicate worker dispatch/result must not perform/adopt effects twice. Keep existing Runtime.Close worker draining and retained receipt discipline.

After binding, no-edit save may use the actual sourced same-file no-op only when candidate bytes match that anchor and approved session semantics. Further edited same-name save remains unsupported existing-file replacement; permit only separately supported sourced Save As to an absent name. Any later successful Save As likewise needs a verified acquired new anchor before switching the active guard/name. OriginalExport never substitutes for current payload/last saved bytes. Source-stale/overwrite refusal cannot be escaped by selecting the source-less route.

## Alternatives, consequences and retained work

Rejected: nil-source overload (weakens existing callers); dummy loaded fixture/storage source (fabricates identity); separate new-file transaction (duplicates security/fault ownership); exporting mutable document state (breaks cursor/history receipts); returning genesis bytes from OriginalExport (lies about loaded input); reparsing current document after save to change origin (discards native revision/history identity); clearing source on stale-save error (bypasses guards); template normalization (loses unrelated native relationships).

Accepted cost: two public publication types with one transaction, private lineage memory, an additional acquired-anchor read and a published-but-unbound safety state. These costs make caller responsibility explicit and keep the early storage package independent of later native research. This is an architectural choice, not evidence that the original uses these internal concepts.

All38 obligations,91 groups,36 workbook lessons and nested leaves remain. Existing-file overwrite/backup/recovery and durability, full native/companion formats, full search/macros/merges, return/formatting/layout/printing, original resources/languages/graphics/historical DOS and physical input remain M1. New absent-target creation does not solve any of them wholesale. No full requirement/scenario closure, acceptance, merge, M2 or PDF is authorized by this decision.

No source, primary planning, task/lifecycle state, guest or evidence commit was changed. The report and manifest are temporary architecture handoffs only. WP40's now approved recipe already includes immediate post-Restore history reinspection; no amendment is proposed here.
