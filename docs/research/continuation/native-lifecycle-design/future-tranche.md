## Recommendation

Prioritize **roundtrip editability and native new-document lifecycle** before adding more narrow character/formatting commands. Original Retrieve/Save reorganizes a324-byte prefix into564-byte/deleted/slack variants, and the current writer refuses those valid outputs for mutation. That safety boundary must stay until independently qualified, but a constructor alone would recreate the same editability cliff.

The coherent eight-package proposal below separates early storage capability, original field research, document semantics, editor state, executable interaction and conformance. Ordinary search, hard returns and Bold creation should be separate subsequent tranches rather than squeezed into this one. Their actual manual/case leads are retained below. Existing25→26→27→28→29→31 and35→36→37 work is not duplicated; all full-M1 gaps remain.

### Prefix expansion is a prerequisite, not a normalization project

WP23's contract explicitly says324→564 can contain deletedFFFF entries, relocated live packets, and later index-unowned/slack regions. These are accepted native observations, not corruption. Neither allFFFF data nor all unowned bytes can be declared harmless merely because a reader accepts them. The next field investigation must classify their live/dead relationships and any body/reference coupling. Preserve literal bytes and ordering; do not compact, rebuild to324, clear counters, or call every original re-save editable.

The original25 interoperability outputs provide corroborating examples, but the new research must not depend on the document/UI execution lanes: it can reproduce the relevant original transitions from approved23/22/14 inputs. Cite later25 outputs immutably when approved; do not turn that citation into a code-lane dependency cycle.

## Blockers and remaining research

1. **Unsourced publication and constructor design:** actual `PreparePublication` requires a loaded storage.Document. Architect must settle explicit new-origin and immutable identity semantics, initial/default/resource state, `OriginalExport` meaning for constructed images, and source-less publication validation. Existing sourced guards cannot be removed; no chosen API is claimed here.
2. **Resaved prefix safety:** deleted packets, stale/slack extents, counters/hashes, active references and possible FastSave body ownership need exact field authority before widening admission. There is no blanket rule that preservation of unknown prefix bytes makes changed body safe.
3. **Existing-target overwrite/backup/recovery:** still M1 and not solved by A. Follow approved files-platform FP02–FP09; original affirmative overwrite, native backup artifacts, stale/permission/full-disk/short-write/cleanup/uncertain effects and concurrency require an independently reviewed transaction contract. Do not promise atomic compare-and-swap by stat-then-rename or silently replace sourced requests with unsourced requests.
4. **Layout and returns:**14 proves selected text observations, not a formatter. Automatic wrap, dormant returns, soft pages, glyph advance/baselines, font substitutions, hyphenation, margins/columns/notes and original print/preview need declared resources and their own engine/acceptance. Short-return work cannot turn terminal wrapping into document geometry.
5. **Resources/platform:**20 resource-readiness retains historical DOS, graphics/metrics/preview, non-US dictionaries/locales, worksheet producers/links and converter qualification gaps. Installed hashes prove identity, not redistribution rights or behavior. Private resources stay private; no modern spellchecker, converter, font or Unicode normalization is selected as substitute.
6. **Physical input and original breadth:** terminal protocol/PTY evidence does not certify physical Linux function/modified keys, mouse, configuration, network sharing or DOS/Shell/PIF mappings. Complete native companion writing, macro recording/editor/conversion, merge/data, graphics/equations and other original functions remain M1.
