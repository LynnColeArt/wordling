# Proposed original-route source contract

Audience: implementer and independent architecture/source/safety reviewers. PROPOSAL ONLY. No operational permission, source approval or actual original qualification follows from this document.

## 1. Authority and source boundary

Keep the existing TEST `ReferenceController.open_leaf` exact-type `TestGrant`/`TestIssuer` checks and harmless CLI behavior. Add a disjoint original entry in canonical package modules `original.py` and `original_release.py`; never cast, subclass, wrap or relabel TEST authority as original. Original source/deployment policy is a distinct exact validated type and retained registry binding; extending common validation must use an explicit exact-type branch, not duck typing or a caller-supplied validator.

### Selected R1 trust root and exact call graph

The selected authorization boundary is **ROOT's deliberate, review-authorized DIRECT invocation of the fixed `original_release.coordinate_one` function in the SAME isolated interpreter**. It is not a claim that a JSON record or opaque object authenticates ROOT. This is a trusted-host/workflow model: the reviewed ordinary leaf/child code cannot call the ROOT mint path; a hostile same-UID actor, arbitrary Python introspection/replacement code, privileged host or malicious ROOT is outside support. No Unix-root distinction, secret store, signature service or authorization server is introduced.

The sole ROOT entry has this fixed interface and sequence:

```text
original_release.coordinate_one(reviewed_row_id, accepted_bundle_digest, invocation_note)
  1. stdlib-only interpreter/deployment checks, then exact bootstrap/source/class checks
  2. validate immutable accepted bundle; lookup ONE exact closed roster row
  3. record ROOT's actual deliberate invocation, exact row and actual origin/earlier end
  4. PRIVATE _mint_registered_decision(live_root_invocation, validated_bundle, row)
  5. RootTicketIssuer.issue(the_live_decision, source_policy, immutable_leaf_plan)
       -> one registered opaque OriginalGrant, bound also to domain/profile
  6. original.open_original_leaf(source_policy, immutable_leaf_plan, grant)
       -> one opaque OriginalLeaf retaining SAME account/context/P handles
  7. prepare_and_launch(); run_leaf() when delivered by WP105; close/report
  8. return; NO loop, NEXT, retained batch authority or automatic reissue
```

An administration row dispatches only the bounded CONTROL administration described below; it issues no leaf grant and launches nothing. The fixed row determines action/domain/profile; these cannot be supplied as CLI flags, arbitrary paths or worker callbacks. The direct invocation itself must actually be authorized by ROOT for the selected row. `accepted_bundle_digest` and `invocation_note` constrain and document that invocation; neither is permission by itself. Calling an ordinary leaf entry with identical data remains unauthorized.

`_mint_registered_decision` is called only inside `coordinate_one`, after its checks, and has no public worker factory. Its live invocation object and private decision registry are source-owned and one-use. Issuer consumption verifies that exact registered object and its scope; serialization/copy/subclass/field reconstruction cannot recover it. The ordinary TEST CLI is unchanged. `original.py`, protocol/publisher/helpers and child/leaf entry points may consume the minted grant but may not invoke `coordinate_one`, `_mint_registered_decision`, or create ROOT role. An actual call-site gate with a non-vacuous expected caller and mutation check enforces that reviewed-code boundary. Importing a module has no release/administration effects. Arbitrary external code deliberately invoking the trusted ROOT function is not prevented by object opacity; the stated trusted-host boundary is explicit.

### Acyclic approval and invocation bytes

Freeze immutable inventories first: **C** exact route/producer/control source bytes; **K** actual harmless compiled CONTROL candidate and fixed data (or later ORIGINAL expected tools/resources/recipe/Wordling candidate); **P** exact finite data plans; **R** closed row roster; **D** actual ordinary deployment/interpreter/import/rights inventory. P may reference C/K; R names exact P/K rows and fixed grant IDs; D contains installed C/K/P/R bytes and excludes its own inventory file. None references the later ROOT decision. A separate review bundle **B** binds C/K/P/R/D and actual independent review references; B is outside the installed inventory and is not embedded in C. This is a directed graph, not a self-hash.

After that review, the actual ROOT direct invocation produces a new bounded decision record **J** containing B/C/K/P/R/D, the exact domain/profile/row/case/context/repetition/candidate/grant ID and actual time/deadline/ROOT provenance. J lives in ROOT's separate invocation evidence/issuer record namespace; J and its filename/bytes are excluded from C/K/P/R/D/B. The entry verifies all scope facts against the already frozen bundle before private/store/guard effects, then mints the live decision and calls the canonical issuer. J records an actual action; loading/replaying J never creates the live invocation, decision or grant. No source file embeds its own final hash or a future decision hash, and no old review is rewritten.

Sequence is concrete: **CONTROL source + candidate/deployment + finite roster review → actual ROOT CONTROL authorization/direct calls → actual harmless controls → final source/test/safety review → exact WP101 ORIGINAL recipe/roster review → later actual ROOT ORIGINAL direct calls**. No grant or invocation is asserted by this proposal. Source review judges this selected design; it does not need to invent an authorization mechanism.

Original issuance reuses the existing durable TicketStore/LeafAccount/ParentLease machinery with disjoint CONTROL and ORIGINAL kinds/roots/generations (both separate from TEST). Preserve permanent O_EXCL spent IDs, fsync/readback/current identity order, same-book handoff and no-refund/no-recovery semantics. Changed source/plan/repetition never permits reusing a spent ID. Missing/pre-existing/partial/foreign markers, wrong boot/generation or lost reply cannot yield another grant. Original-store administration is a separately authorized bounded prerequisite, never automatic leaf setup.

Before publishing a grant, durably retain a nonterminal safety reservation under the same original store. An unresolved reservation blocks issuance for other IDs too; kernel release of a dead coordinator's lock must not be interpreted as safety. This is a refusal predicate, never persisted authority from which to recover a grant. WP105 may terminally discharge the reservation only from the same actual retained context's genuine stopped/containment/export proof. Loss/partial persistence/UNKNOWN leaves it quarantined; no automatic recovery, generation switch, deletion or new-ID escape. This uses existing finite store/book/record primitives; if it needs a new generic account/P API, split and review that prerequisite before implementation.
