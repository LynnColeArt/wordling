# Full-M1 family continuation map (proposal only)

This maps all58 current open rows and all91 parents/36 lessons without treating the244-scenario catalogue as exhaustive. Symbols below are planning slice IDs, not official WP numbers. No runtime finalization is requested until Spec Kitty accepts IDs100+ and the owned checkout/auth policy is honestly resolved. Initial executable detail is WP100–103; remaining families need source/contract research and exact, independently reviewed task/source declarations before code claims. A family with multiple named deliverables must split into the stated smaller WPs.

## Shared prerequisites

- **coverage-index**: WP103 census and then bounded source study for every family/lesson; discovery expands, never caps, the queue.
- **reference-route**: actual original-authorized controller/source closure. WP101 cannot substitute TEST or expired grants; any controller correction gets its own reviewed source/design amendment.
- **resource-census**: current private presence/hash/licensing/producer matrix; do not confuse unavailable with uninspected. Existing tools/master paths are present, but safety/readiness/hash checks precede each use.
- **native-relationships**: the existing approved original-format reader/writer/owner APIs plus exact new relationship research before broadening. Existing unknown bytes/opaque packets remain protected.
- **layout-profile**: fixed actual current native/default/printer geometry and tolerances declared before comparisons; no text-display inference from printer labels.
- **graphics-font-profile**: acquire/pin a graphics/proportional-font/printer/feeder-capable original profile and admissible input corpus before those fidelity claims.
- **language-profile**: lawfully private HYC/LEX/THS/other original language resources, declared decoder/behavior contract and missing-resource failures.

Each parent family gets complete chapter/subcommand/appendix/error/resource/menu leaf census; split into3–5 related command leaves per implementation WP after research. These are bounded research/replay work items, never one giant “finish workbook” implementation.
