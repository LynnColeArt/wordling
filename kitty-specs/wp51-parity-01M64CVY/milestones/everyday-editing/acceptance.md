# Everyday editing acceptance journeys

These journeys define milestone completion. Each row expands into an original-app transcript and an equivalent Wordling executable transcript during WP78. Exact prompts, default choices, cursor positions, highlighted cells and native results come from the pinned original. The exploratory board is a starting observation set. A scenario with only a screenshot or only a passing internal unit test remains incomplete.

## Required evidence for each journey

Record the original executable/resource/profile hashes, initial fixture hashes, original and Wordling inputs, synchronization checkpoints, character/attribute grids, cursor/focus state, file effects, native output hashes and final outcome. Original and product runs use the same semantic content and settings. Wall-clock timestamp fields may be compared separately where they are intrinsically variable. Every masked field needs a recorded reason before comparison. Do not mask menu selection, printed position, filename, dirty state or document content.

Run reference scenarios on fresh private VM copies and preserve failed observations. Repeat the uncertain and newly authored reference sequences successfully before using them as regression expectations. Explicitly read the displayed reference release. Product runs exercise the normal CLI and real filesystem; helper constructors and fabricated completion messages are supplemental tests.

## Visual comparison rules

Original VGA observation is 80×25 character cells rendered at 720×400. At that profile compare logical cells, character identity, attribute roles, menu geometry, active focus and cursor position exactly for accepted frames. Screenshots document font/raster appearance. Linux terminal glyph rasterization can differ, but such differences cannot excuse wrong logical layout or color roles. Record terminal type, size, font where known and key delivery.

At larger and smaller Linux terminal sizes, verify visibility, clipping/scrolling, input focus and safe rendering. Keep paper geometry fixed. The Linux adaptation contract must state how the reference-sized canvas is positioned or extended and how mouse coordinates map to it. Do not equate fullscreen terminal columns with document margins.

## Native and layout comparison rules

Use original-produced inputs and the same native reader for product reload checks. No-edit outputs require exact bytes. Edited outputs require exact intended semantic effects, preservation of unrelated data and original interoperability. Where the original recomputes derived native fields or soft returns, explain the transformation using recorded original evidence and compare its meaning and affected ranges. A blanket byte-normalization script is insufficient.

Matched-profile physical positions and page breaks have zero unexplained differences. Any necessary rounding/rendering tolerance is recorded before the scenario runs. The core supported fixture family must produce real values; placeholders cannot satisfy the milestone.

## Review and completion

Implementation and review are separate identities. Reviewers inspect the current diff, normal callers, acceptance evidence and remaining unsupported routes. Rejections return to the package that owns the behavior and trigger the affected downstream checks after repair. WP86 independently reviews the full integrated journey even if every component package has approval.

Complete a matrix with every EE requirement and acceptance ID, original evidence path, product evidence path, reviewer verdict and build identity. Keep the broader M1 requirements open. No overall parity completion percentage is inferred from the number of approved work packages.
