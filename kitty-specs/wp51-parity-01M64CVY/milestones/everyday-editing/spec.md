# Everyday editing milestone

Mission `wp51-parity-01M64CVY`. Planning target `feat/wp51-parity`. Authored 2026-11-05 under the user's instruction to turn the original-app study into a complete, faithful everyday editing milestone, then implement and independently review it. This is an amendment within M1. Full M1 acceptance and M2 remain governed by the existing charter and mission specification.

## Product outcome

A writer can start Wordling, browse and preview a native document, retrieve or create text, navigate and correct it, apply Bold and Underline, inspect and edit its codes, search, proofread in context, save, continue editing, reopen, and exit through the original prompts. This whole journey works in both document screens and after repeated saves. No step in this journey ends in an unimplemented transition or depends on a pristine startup buffer.

The March 9, 1992 US WordPerfect 5.1 executable remains the behavioral reference. The [visual study](../../../../docs/research/ui-study-2026-11-05/index.html) supplies hypotheses and concrete screenshots. Its one-session observations become verified expectations only after the repeatable reference work in this milestone. The complete [mission specification](../../spec.md), [compatibility contract](../../../../docs/compatibility.md), and [charter](../../../../.kittify/charter/charter.md) remain binding.

## Reference configuration

Use the fingerprinted QEMU/FreeDOS/Standard Printer environment already registered in the repository. Record its limitations, exact disk and executable identities, printer resources, keyboard definition and changed setup settings for every run. Begin screen comparisons at 80 by 25 cells. Match paper dimensions, margins, font pitch, line height, tab stops, justification and hyphenation in both applications before comparing layout. The follow-up original Format → Line capture reports Full justification, Auto line height, line spacing 1, one-inch left/right margins, Hyphenation No, relative tabs beginning at minus one inch with half-inch intervals, and Widow/Orphan No. These defaults are now recorded in the repeated [everyday reference contract](../../../../docs/research/everyday-contract-2026-11-05/REPORT.md). Preserve Full justification in layout qualification. The selected Base Font is Courier 10cpi and the page is Standard 8.5 by 11 inches with one-inch top/bottom margins. The repeated sample supports one-sixth-inch line advance. General Auto line-height, justification, tabs and pagination still need the broader WP78 observations before implementation claims.

The user-facing preview begins with the original Menu Bar Remains Visible preference enabled, using the original setting and focus behavior. Both Yes and No are tested. Alt+=, original function keys and original modifier families control the app. Ctrl+S, Ctrl+O, Ctrl+Q and other modern aliases are disabled in the milestone launch configuration. Terminal delivery differences are documented separately from command behavior.

## Milestone fixture family

The complete everyday journey is required for native WP 5.1 documents containing representable US text, spaces, tabs, hard and soft returns, ordinary page boundaries, and Bold/Underline codes under the matched Standard Printer profile. Cover both original-produced and Wordling-produced documents, including prefixes and unrelated opaque data that can safely remain untouched. The fixture family includes empty documents, one-line documents, the two research samples, multiple paragraphs, long words, nested/overlapping attributes where the original permits them, and at least a three-page document.

These are coverage fixtures rather than arbitrary product size or attribute-count limits. Retain explicit measured resource bounds. A loaded document in this family cannot be rendered editable and then refuse ordinary editing because of its creation lineage or save history. Broader original character sets, alternate resources and complex document structures remain full-M1 obligations in the existing inventory.

## Completeness boundary

All commands and transitions needed by EE-001 through EE-015 must work. This milestone does not complete all functionality named in every original menu. Remaining print options, tables, advanced styles, graphics, macros, merges, language tools beyond the accepted proofreading journey, import/export modes and utilities retain their existing mission requirement and inventory status. List Files copy, move/rename, deletion, disk printing and advanced file utilities retain their existing FR-006/015 obligations unless a concrete acceptance journey requires them. Their absence cannot be disguised as an original context-disabled state.

Menus may reproduce the complete historical vocabulary while the development build reports a missing implementation honestly outside the accepted journeys. The acceptance report must enumerate those reachable gaps. A supported everyday command must never use that development message. Existing working commands outside the milestone retain their behavior.

PDF export and newly invented convenience shortcuts remain M2 work. The milestone closes only its own requirement matrix. It cannot justify `accept` or `merge` as completion of the entire parity mission.

## Proofreading is a priority product journey

The user's further direction prioritizes the original proofreading experience as a potential strength of a terminal word processor. The acceptance target is sustained reading and correction in context. It includes the original scope chooser, highlighted questionable word, suggestions and action keys, advancing through multiple occurrences, editing around a questionable word, returning to the proofing pass and resuming ordinary document editing.

The initial original study reports Ctrl+F2 scopes Word, Page, Document, New Supplementary Dictionary, Look Up and Count. During checking the original retains document context above a ruler, shows lettered suggestions below and offers Skip Once, Skip, Add, Edit, Look Up and Ignore Numbers. The reviewed contract must establish the exact wording, defaults, suggestion pages, automatic replacement of subsequent occurrences, per-pass Skip behavior, dictionary persistence and F7 return from Edit. No modern spell-checker assumptions replace these observations.

Original dictionary/resource identities, format support and redistribution rights must be declared. Proprietary dictionaries are never bundled without permission. The selected reference resources and the product's actual admitted resource source must be available to acceptance runs. Resource absence or lexical differences remain explicit and cannot be hidden behind an empty suggestion list or unconditional success. Any alternative licensed lexical provider needs a reviewed adaptation contract that distinguishes workflow fidelity from lexical/ranking equivalence. Milestone acceptance requires a real working resource-backed proofreading journey.
