# Selected internal interfaces and finite support model — design only

## 1. Typed binding/callflow

The outer reviewed ReferenceController.open_leaf/run_leaf/close remains unchanged. No outer API accepts a ledger, permit, parent, budget, normalDOS/stop fact or release boolean.

Internal proposed interfaces under internal/document/evidence/reference_controller/:

- **LeafAccount.reserve_ledger_operation(kind, bound_owner, limits)**: called only by the retained trusted controller/account path after actual authorization, before effects. It reserves/spends the conservative maxima in the SAME leaf envelope and creates one issuer-held LedgerOperationPermit. It has no ability to enlarge the reviewed grant/envelope or manufacture P credit. Valid kind is acquire-parent, create-ledger, update-record or cleanup-close. Limits are selected from frozen plan maxima, never user replacement counters. A consumed/lost operation cannot be reissued. Cleanup headroom is reserved at authorized leaf entry and stays spent.
- **ParentLease.acquire(absolute_parent_path, acquire_permit)**: new source-defined ownership factory. It consumes an authentic acquire-parent permit, walks/retains the actual allowed root/components and returns a nonconstructible retained directory capability to trusted controller only. No copied stat/path/JSON is a ParentLease. A failure consumes the operation and prevents setup/launch; actual partial descriptors get bounded cleanup.
- **OwnedLedger.create(parent_lease, basename, create_permit)**: consumes its actual account's create permit bound to THAT ParentLease/name, creates the absent locked ledger relative to the retained parent, then the account privately binds that exact new ledger object/identity. No constructor/path/expected_parent=None compatibility with oldOwnedFile. The class constructor is internal; there is no public proof/handle reconstruction.
- **ledger.write(record, update_permit)**: source-owned permit is bound to THAT actual ledger, parent and next operation ID. It is atomically marked consumed/active in the live account BEFORE bounded record preflight. Only that active source-defined operation may step through validation, encoding, write, truncate, fsync, verify and readback. No callbacks/plugins/duck-typed token accepted. Result is diagnostics/success only, not another permit. Copied records/permit projections cannot authorize.
- **ledger.close(cleanup_permit)** and **parent.close(cleanup_permit)**: trusted cleanup with the original reserved containment/close allowance; no new reservation after exhaustion/HALT. Records truthfully include failed close, outstanding/unproved persistence and logical safety hold. Detach/track owned descriptor identity so repeat close never closes a recycled foreign fd. No unlink/reopen/recovery.

Exact permit class, account and private live registry are defined in canonical account.py; ownership/records import that actual module/type via ordinary package-relative imports. Internal issuance requires the account/controller issuer, not a public bool/nonce/factory available through CLI. Ledger checks actual class AND issuer-object identity/live active record/bindings. Python source-private capability discipline is not a hostile arbitrary-reflection sandbox. This explicitly permits these reviewed internal types; the earlier blanket “no dependency-object injection” continues to prohibit arbitrary substitute implementations, global/module patches and caller callbacks, not genuine source-issued operations.

Limits reserve the entire record's finite upper bound (including work of both passes and copies), all bounded read/write/syscall maxima and time origin before use. Full reservations stay spent on success/failure/loss. Step checks validate actual time.monotonic_ns and remaining operation counters before/after each piece, then update actual-use diagnostics WITHOUT returning credit. No separate clock reset or ledger-level aggregate-credit estimate. Any I/O/error/lost persistence means no later noncleanup operation. Parent acquisition/create and initial durable charge are part of the authorized ticket: if durable charge cannot be proved, result is SPENT/UNKNOWN/PERSISTENCE HALT, never zero/retry; the root safety decision stays distinct.

## 2. Versioned record schema and value model

LedgerRecordV1 is an EXACT builtin dict with exactly these top-level keys:

- schema: exact string `wordling.reference-controller.ledger/v1`.
- leaf: exact builtin str, nonempty<=128 ASCII characters, source/plan-bound identifier.
- sequence: exact builtin int (not bool),0..2^63−1, monotonic operation sequence checked by account.
- state: exact str selected from AUTHORIZED, CHARGED, SETUP, RUNNING, STOP_COLLECTING, STOPPED_ISSUED, EXPORTING, PHYSICAL_RELEASED, AUDITING, COMPLETE, HALTED. These names record the reviewed lifecycle; serialized state NEVER advances it.
- source: exact builtin dict with keys binding and plan; each exact64-character lowercase hex digest for the approved source/immutable plan.
- observed_ns: exact builtin int0..2^63−1 from source-owned monotonic time; not a supplied deadline/credit authority.
- facts: exact builtin dict of bounded diagnostic values below. Optional facts are inside this required dict; unknown top-level keys refuse.

Values in facts: only None, exact bool, exact int in [−2^63,2^63−1], exact str, exact list and exact dict with exact str keys. No float of ANY kind (including finite/NaN/Inf), bytes/tuple/set/subclass/custom mapping/iterator/callable/other object. Integer checks inspect exact builtin type/bit_length before conversion; bool is handled separately. No int()/str()/iteration hooks on user objects. Each dict key is ASCII [A-Za-z0-9_.-],1..64 characters, no duplicate after capture. Strings allow Unicode scalar values except surrogate code points; validate them with bounded per-codepoint work, no normalization. Containers are read-only for the operation by trusted caller convention: no simultaneous mutator/worker receives the record. Reject ANY repeated mutable container identity, including acyclic shared-list/shared-dict aliases as well as cycles; repeated immutable scalar values are allowed and charged each occurrence.

Reviewed maxima, task may tighten but never widen silently:

- encoded record <=256KiB; selected required max_record_bytes in [1,256KiB], no implicit32MiB default;
- depth<=8 including top-level; total values+keys<=4096; individual list/dict entries<=256;
- each string<=4096 code points; total key/string code points<=32768; integers<=64bits signed;
- private traversal/encoding work<=262144 charged units per operation; worst-case reservation fixed before traversal;
- output chunks<=4096bytes; record buffer<=selected max_record_bytes; at most64 output chunks plus one final empty boundary check; readback requested in<=4096byte pieces; all attempts/syscalls/time additionally capped by permit.

Additional fixed reviewed operation ceilings: acquire-parent<=256 filesystem syscalls and<=33 retained ancestor fds; create-ledger<=256 filesystem syscalls; update-record<=1024 filesystem syscalls total,<=256 positive-write attempts,<=65 readback requests, and transferred write+read bytes<=2*selected_max_record_bytes+1. Excess short-progress attempts refuse even when bytes remain. Retained ledger adds at mostone fd; cleanup-close reserves<=64 close attempts across the held chain/file. Identity/link/stat/time checks are included in syscall/work reservations, not hidden outside them. Encode/readback buffer+copies have a conservative selected reservation<=4*selected_max_record_bytes+1MiB; process RSS remains separately bounded/measured under the common envelope, not inferred from that allocation estimate. Per-operation fixed ceilings are tightened when the actual common envelope cannot fund them; insufficient reservation means refusal BEFORE operation. No effect may use a theoretical ceiling above actual remaining leaf credit.

If a real required diagnostic record does not fit, BLOCK before prelaunch or issue a separately reviewed tighter summary/schema amendment; do not truncate native/evidence, silently increase limits or hide a partial failure. Binary outputs/large receipts/raw captures stay in separate typed byte publisher artifacts under their own envelope; facts contain bounded locators/hashes/diagnostics only.

## 3. Serialization without pre-limit overspend

The account reserves the maximum work/copy memory/metadata/IO first. Source-owned records.py performs TWO bounded traversals; no product callback and no generic whole json.dumps/default/encoder dispatch.

Pass1: validate exact top-level schema and exact builtin types; check O(1) builtin len/bit bounds BEFORE entering a container/string; cap node/depth/entry counts and the visited-container set before pushing children. Reject repeated container identities (both aliases and cycles). Inspect at most permitted codepoints, including exact surrogate rejection. Charge one unit for each node/key/codepoint inspected and each bounded encoding contribution. Conservatively sum JSON encoded upper bound using checked integer arithmetic: each scalar-character at most12 ASCII bytes for JSON escaping, exact bounded syntax/key separators/brackets/indent2/LF overhead, exact bounded integer spelling. Stop before adding an over-limit unit/byte/node/entry; no reading a whole huge input just to learn it is huge. Builtin len of huge string/container may be inspected then refuse without traversing it. No allocation proportional to rejected length.

Pass2: only the validated, exclusively held exact builtins are encoded deterministically in insertion order, indent2, ASCII escaped JSON (ensure-ascii semantics) plus ONE trailing LF. Escape spelling/surrogate-pair rules must match documented standard JSON/CPython ensure_ascii conventions; integer/bool/null spelling fixed. Recheck type/length/budget/active operation before each bounded piece; no sorting/normalization/user dispatch. Each chunk<=4096 and aggregate<=selected bound. Accumulate the bounded final encoded bytes BEFORE ledger write, so all validation/encoding failure leaves prior ledger bytes untouched. Total buffer memory is capped by selected max plus bounded traversal stack/visited metadata; source tests measure actual allocator/RSS under the common envelope rather than claim byte limit equals process RSS.

An overconservative upper bound may refuse a record whose actual encoding would fit: this is supported conservative refusal, never bypass by encoding first. Mutation between passes/unsupported alias/source/context loss refuses before write where detected; trusted same-worker no concurrent record mutation is an explicit support assumption. No atomic snapshot of arbitrary concurrently mutating Python objects is promised.

Write phase: use ONLY the held owned fd, verify all identities/links, positive bounded writes of encoded chunks, bounded truncate/fsync/verify, exact bounded same-fd readback comparison. Count actual transfer attempts; zero progress or lost/short-unprovable IO HALTs, no unbounded retry. Encoding is not a second QMP/native parser; readback is byte equality, not restoring capabilities from JSON. No atomic rollback/power-loss durability promise.

Use a purpose-built ordinary venv with include-system-site-packages=false and a normally installed source-reviewed wheel for reference_controller. Packaging metadata/entry files are owned in the new namespace; no editable installs, zip imports, symlinked package, network download/runtime installer, PYTHONPATH or cwd-selected source. Standard package __init__.py is empty; __main__.py delegates only to a minimal stdlib bootstrap. No ownership/account/peer/P/controller imports until bootstrap validation completes.

Trust/order is EXPLICIT:

1. Before starting this interpreter, trusted ROOT/test coordinator validates the selected deployment manifest and its retained absolute root/interpreter/package origins: exact interpreter/version/base-prefix/pyvenv configuration, declared stdlib/extension closure, installed E wheel/file hashes, site roots, permissions/identities and fixed invocation. 2. Coordinator retains logical exclusion of deployment/source writes for the invocation; writable-to-untrusted actors or mutable/unproved root refuses launch. Checks do not atomically freeze a hostile filesystem between hash and import. Support requires the trusted immutable-for-invocation deployment/exclusion assumption; detected inconsistency blocks, adversarial undetectable change-and-restore is outside that guarantee and cannot be claimed prevented. ## 5. Retained-parent/component policy

ParentLease factory accepts ONLY a frozen absolute local-Linux parent path from authorized source/plan, not cwd-relative/arbitrary caller root. Maximum32 nonempty components, each<=255 encoded bytes, total<=4096bytes; reject '.', '..', repeated separator, NUL and symlink at ANY component. No automatic mkdir in the low-level factory; any selected controller-owned directory creation is its separately reserved source-defined operation and must return a validated capability before ledger use.

Open `/` as retained directory fd, then walk each component relative to the previous fd with O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC. Hold every ancestor fd and (parent-fd,name,child dev/inode/type) association, no proc/private-P descriptor borrowing. Verify each fstat/fstatat(no-follow) link matches the just-opened descriptor; capture final actual parent and the selected namespace root/source/leaf/account binding. FD maxima are reserved before the walk. ParentLease constructor is internal and issuer-retained; copied stat values/paths/fds/JSON are not accepted. Ledger basename is one ASCII [A-Za-z0-9_.-] name1..64, not '.'/'..', no slash; create only relative to that retained final fd with O_EXCL|O_NOFOLLOW|O_CLOEXEC,0o600 and nonblocking flock. Existing target refuses; no unlink/replace.

Before each ledger operation, before first write, after write/fsync/readback and before reporting success, revalidate EVERY retained ancestor link from root and the current parent+file fd/path identity/regular type/single-link state. Actual descriptor-relative IO continues to target the retained owned inode, never a new pathname replacement. Any observed ancestor rename/substitution/unlink, mount/namespace/identity/link/type ambiguity or descriptor loss HALTs and denies later effects. A capability from another leaf/root/issuer or closed/stale generation refuses even if dev/inode facts happen to match.

Support is a stable local Linux filesystem with required directory-fd/no-follow/exclusive-create/flock/fsync semantics and a fixed mount namespace; network/FUSE/unproved semantics BLOCK unless independently qualified later. These operations do NOT make pathname checks and writes atomic. A concurrent external rename may cause an attempted write to the same retained owned inode before the later check detects changed path; report partial/uncertain and HALT, never claim zero effects or a successful publication. Repeated undetected change-and-restore or adding/removing an external hardlink between checks is not prevented. Trusted exclusive owned-parent namespace/no external mutation is a required support premise for stronger single-owner claims. Unknown FS/ancestor safety never upgrades through a copied expected_parent or permission boolean.
