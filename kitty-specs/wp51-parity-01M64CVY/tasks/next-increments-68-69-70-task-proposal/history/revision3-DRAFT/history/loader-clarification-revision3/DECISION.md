## Permanent consume proof point

The RootTicketIssuer's ONLY successful original issuance is one trusted ROOT-coordinator operation, with source-bound one-leaf decision, exact selected plan/budget/deployment and a pre-provisioned store capability. The preliminary decision/request is NOT a grant. The operation:

1. Performs source/ROOT-or-TEST authority/plan/store/current-clock checks, allocates the bounded bootstrap reservation from the SAME eventual leaf book and marks its local request attempted; still no parent/setup/launch permit exists.
2. Opens **one permanent final `<stable_key>.spent` file with O_CREAT|O_EXCL|O_NOFOLLOW**, relative to its retained pre-existing TicketStore parent. Creation is the kernel namespace linearization point: any existing object at this name, even empty/partial/foreign, causes permanent refusal, never replacement/recovery. Never unlink it on failure or completion.
3. Writes the bounded fixed ticket binding, fsyncs its actual retained fd, fsyncs actual parent, and rechecks the complete store chain/file/source/binding/clock. Durable issuance proof is this complete successful sequence plus its actual retained operation history, NOT a returned hash/stat/JSON.
4. Stores a private live issuance record and creates ONE nonconstructible NEWRootGrantFile bound to that exact durable ticket/account/source/leaf/budget/origin. The SAME reference is handed once to trusted open_leaf; public CLI/report serialization exposes diagnostics only. No grant capability exists before3, and no startup/ledger/resource/setup permit can be issued before this actual grant is consumed internally once.

The account's first per-leaf setup is therefore preceded by an independently bootstrapped durable permanent charge. A process loss after3 but before parent/create/first ledger write leaves the ticket spent and loses the capability. A fresh process cannot reconstruct it from the ticket or a copied grant file. The existing source-owned one-use operation permits then enforce F1 inside the live account, while the permanent ticket prevents new-process replay.

## Failure/restart semantics

Any created ticket remains consumed even if its content/durability/final result is unknown. No retry/fsync-resume/handoff recovery. If creation itself failed before an owned ticket existed, no actual grant was issued and NO per-leaf setup was authorized. Report an ISSUANCE_FAILED/UNKNOWN outcome separately, not a successful no-effect leaf; do not call it a refundable authorized leaf. There is no automatic root issuance-request retry: a new ROOT decision is separate, and cannot revive an old issued/possibly-issued grant. A copied preliminary request cannot enter open_leaf.

Process restart with the same store/key always encounters any existing permanent tombstone and refuses BEFORE a new account/bootstrap permit. A lost result/capability after durable issuance is terminal even if no OwnedLedger exists. Restart never reopens the tombstone as authority. Host reboot/storage-recovery is NOT account recovery: store generation is bound to the selected boot identity; mismatch/unproved fsync/local-FS recovery quarantines that generation and all its prior identifiers. No old grant is reissued under a new generation. Explicit new store-generation administration is a separate ROOT action/authorization, never run_leaf or automatic cleanup. See ISSUER.md for exact stable-key, trust, support and finite setup rules.
