## F1 — Bind the advertised remaining-credit/deadline checks through a specified API

Blocking clauses: API-AND-FLOW.md:11–13,20 and unchanged one-leaf envelope/callflow; ACCEPTANCE.md:4–6.

The only declared construction inputs are path, expected_parent and max_json_bytes, followed by write(record). The write contract promises enforcement of remaining ONE-leaf metadata/time credit, but no constructor/internal binding carries the selected absolute end or actual cumulative reservation authority. max_json_bytes is a per-record size ceiling; it cannot determine actual remaining allowance after earlier writes, binary publication or protocol work. The new module may import only stdlib/local errors, and dependency-object injection/global repair is forbidden. Therefore a task author would have to invent a binding path or quietly move enforcement elsewhere.

Required revision: choose and specify who reserves/charges aggregate metadata/IO before ledger effects, how the actual retained ledger is bound to the selected absolute deadline and operation reservation, and where fresh checks occur during serialization/short-write/readback loops. If the trusted controller owns a dimension instead, state its exact pre-effect reservation and ledger call contract and remove any stronger autonomous-ledger enforcement claim. Preserve full spend/sticky HALT on unknown/partial/persistence loss; no caller snapshot, boolean, refund or grant authority. This is not a request to import P private fields or introduce a second supervisor.

## F2 — Define a genuinely bounded finite JSON value/serialization contract

Blocking clauses: API-AND-FLOW.md:13,17 and ACCEPTANCE.md:3–5.

“Schema-approved finite JSON” and a32MiB encoded maximum do not specify the new accepted record/value model, traversal/serialization bound or schema. A finite but huge/deep/cyclic container, oversized integer/string or user-defined object can consume unbounded work/memory before the encoded length check or trigger unspecified dispatch. Saying selected max is enforced BEFORE write protects file mutation but does not establish bounded serialization. The historical class itself json.dumps the full object before checking length (approved51 accounting.py:19–20), so semantic resemblance cannot supply the missing guarantee.

Required revision: define the closed accepted scalar/container types and record-schema boundary, finite depth/node/string/integer/encoded-byte accounting (or equivalent explicit bounded model), cycle/nonfinite/unsupported-object behavior, and an encoding/preflight strategy that cannot allocate/traverse beyond the selected budget before refusal. Exact tunable constants may be task-selected within reviewed maxima; the value and resource model cannot be left implicit. Bind failure classification and no-write/partial-write semantics to the real phase. JSON fields must remain diagnostics/state data and cannot mint stop/export/release authority.

## F3 — Select the ordinary bootstrap and parent/ancestor identity rules

Blocking clauses: API-AND-FLOW.md:11,20,26–30 and ACCEPTANCE.md:1–3.

The document fixes source paths under internal/document/evidence/reference_controller, names a canonical reference_controller package, prohibits runtime path/module/AST/loader tricks, but leaves the actual supported standard package/bootstrap invocation and import environment for implementation to document. Those choices determine which package executes before origin validation; a post-import hash check cannot by itself establish the promised before-effect closed-root behavior. This is the precise defect class being removed from the old loader, so it needs a selected lawful entry rather than “BLOCK if startup cannot establish it.”

Likewise expected_parent is described as an identity cross-check, without a concrete type/representation or rule connecting the controller's retained actual parent capability to the class's path open. The text correctly admits terminal O_NOFOLLOW does not bind ancestors, but delegates its component/ancestor policy to future source. It does not yet say which components may resolve/symlink, what root is trusted/retained, when descriptor/path identity is checked or which racing-filesystem uncertainty is accepted versus refusal. A task author cannot promise exact parent identity merely from copied stat facts and a terminal nofollow flag.

Required revision: name the actual standard public launch/module name, trusted interpreter/import/cwd/search-root assumptions and source-check ordering before owned effects, including cache/foreign-root refusal. Specify the retained-parent argument/association and component/ancestor policy with truthful residual race guarantees. Keep exact source/class identity, no legacy fallback, no runtime sys.path/sys.modules replacement, no AST extraction and no fake frames/boundaries injection. This finding does not demand a prototype or a hostile in-process sandbox; it asks for the design decisions needed to author an honest implementation task. Any remaining approved-peer bare-import closure remains its separately disclosed blocker, not solved by this ledger decision.
