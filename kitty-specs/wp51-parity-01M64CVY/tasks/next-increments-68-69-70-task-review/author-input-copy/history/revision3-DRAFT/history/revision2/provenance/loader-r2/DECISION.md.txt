## F1 selected: account reserves; typed operation permit binds ledger

The source-owned common ONE-leaf account owns aggregate remaining credit and the immutable earlier absolute origin/end. **The ledger does NOT infer/enforce aggregate allowance autonomously from max_json_bytes.** Before parent acquisition, file creation, each record encoding/update or close/cleanup, the actual retained account reserves the entire conservative maximum for that operation from the SAME leaf envelope, spending that reservation permanently. Earlier protocol/binary/P work and outstanding/lost reservations remain counted. No refunds/reset from actual-low usage, copied UsageObservation or a new ledger operation. A full-spend policy avoids a second resource-credit algorithm.

Its private issuer returns a genuine one-use LedgerOperationPermit bound to exact account/leaf/source/plan/grant-or-TEST/generation, retained parent/ledger identity, operation ID/kind and immutable absolute_end_ns, selected record/encoding/work/IO/syscall limits and the reserved cleanup margin. Numeric fields/projected permit diagnostics cannot authorize. The common account keeps a private live record; OwnedLedger accepts only the exact actual permit type/object from its captured account issuer, then asks that SAME source-owned account to consume its live record BEFORE any encoding or IO. This is an explicitly selected typed internal capability boundary, NOT arbitrary dependency callbacks/global injection. No caller-supplied budget object, clock, predicate or reservation snapshot is accepted.

Source root modules are concretely account.py (existing required new one-leaf issuer/envelope/reservation), ownership.py (ParentLease/OwnedLedger), records.py (bounded encoding), errors.py; all in the NEW common namespace. ownership.py imports its canonical local permit type/validation from account.py; account.py does NOT import ownership or run controller/supervisor/P. Account binds opaque parent/ledger identity objects on issue, with no filesystem effects in that module. Trusted controller composes them. All modules are new proposed code with no source hashes yet; this is not importing an implemented private API.

Ledger/encoder use the permit's source-owned validation/step check before and after every bounded traversal/encoding piece, every short-write/readback piece and every filesystem operation. That check uses actual time.monotonic_ns, exact active operation/account/leaf state, operation work/IO counters and immutable absolute end; no injected clock in production. Per-operation maxima were fully spent at reservation and cannot grow. Any expiry/limit/IO/persistence/source/identity uncertainty burns all reserved credit and irreversibly HALTs the account; no later operation permit except already reserved containment/close diagnostics. The bookkeeping cannot make a blocking syscall preemptible: selected local regular-file operations are not a hard real-time/sandbox guarantee; post-call expiry prevents later effects and cannot certify success. Cleanup uses its pre-reserved margin, not new time/credits.

## F2 selected: closed record model plus bounded preflight and encoding

Records are versioned source-defined one-leaf state/diagnostic data, never capabilities. No generic arbitrary JSON object acceptance or unbounded json.dumps. Exact types/schema/maxima and two bounded passes are in CONTRACT.md. Before traversing the record, the account reserves its selected WORST-CASE traversal/encoding/copied bytes and file IO. Before creating encoded bytes the encoder validates exact builtin types, schema, sizes/depth/nodes/cycles and a conservative encoded upper bound. Unknown classes/callables, iterators/custom mappings/str subclasses/objects/sets/bytes/floats/NaN are refused without invoking user methods. Time fields are integer monotonic ns, never floats. Actual staged encoding is chunked and byte capped; no unbounded whole-buffer stringify, sorted-key expansion or custom encoder/default hooks. The source-owned work/byte budget applies in BOTH passes.

Preflight/encoding failures happen before ledger writes and leave existing ledger bytes unchanged, but the authorized operation reservation remains spent and the one-leaf account HALTs. Actual partial writes/readback/fsync failures retain truthful uncertain partial state; never rollback/reopen/retry/refund. Diagnostic data cannot issue normalDOS/StoppedRun/export/release/authorization. Per-record budget is distinct from aggregate cumulative metadata/IO/time.
