## Why this option is the minimum maintainable boundary

The required actual class is defined only AFTER51 accounting.py imports frames.Refusal/require. That frames module eagerly inserts scripts/reference into sys.path and imports macro_session/macro_quit.55 owned_file_class checks exact accounting/frames Git bytes, modifies sys.path, executes the old module and caches its class. Literal reuse therefore executes excluded imports before the useful definition is available. Source truth does not imply harmless loading, and we do not execute it here to discover effects. Appending a clean function after the eager import, executing selected AST statements, faking frames, injecting approved globals or changing import order externally cannot fix that boundary honestly.

A clean extraction of the SAME actual class would require changing51 accounting and its callers.55's exact historical source checks would then fail; updating them cascades to new source closures/evidence and changes a retired protocol. A second definition in a new module is a DIFFERENT class even if byte-identical. That is option C and must be specified as such. The new controller already needs independent one-leaf issuer/account logic and a separate byte publisher; allowing a small explicit ledger primitive there is narrower than reopening immutable historical51/55 loader authority.

The new authority implements one current maintained one-leaf ledger boundary, not a second process supervisor, QMP/native/parser or old Batch fork. Old implementations remain immutable historical/protocol dependencies, not hidden interchangeable backends. No fallback to the legacy loader is permitted.
