# Concrete local one-shot issuer contract — proposed E source only

## Roles, store and accepted authority

New source module issuance.py owns RootTicketIssuer, TicketStore and opaque issuance capability. It uses stdlib filesystem/hash/time primitives, canonical local errors and the same source-owned cumulative budget book; no P/peer/native/runner/ledger serializer import or process supervisor. Import is no-effect under R2's already selected trusted deployment. Account/ownership modules do not open the store implicitly. Public controller open_leaf/run_leaf/close signatures remain unchanged; original NEWRootGrantFile means an ACTUAL source-issued file capability, not a raw path, copied JSON or reconstruction API.

Supported original orchestration is a trusted ROOT-coordinator invocation in the SAME interpreter: explicit reviewed ROOT decision → RootTicketIssuer.issue → retained actual grant reference → ReferenceController.open_leaf → run_leaf. There is NO standalone `run --grant-file PATH`, deserialize-grant, recover-ticket, resume or lookup-to-capability mode. Offline public plan/check cannot issue originals. Source/deployment validation alone cannot call original issue: the separate trusted ROOT authorization entry is required, with independently accepted actual code/prelaunch/plan/private-fit/new one-leaf decision. External invocation/roles are trusted coordinator admission, not security against arbitrary hostile in-process code or same-UID filesystem access; JSON fields/flags are never that admission. Actual production original gate stays disabled until separately reviewed; TEST CLI calls a disjoint TestTicketIssuer under source-defined harmless authority and cannot create/return NEWRootGrantFile.

Store is a PRE-PROVISIONED, single-generation local Linux directory owned exclusively by the selected trusted coordinator actor,0700 with0600 regular metadata, no symlink components/network/FUSE/unproved filesystem behavior. Source-bound configuration names its exact absolute path, generation UUID, owning UID, selected host boot identity and authorized kind ORIGINAL or TEST. The actual retained directory chain, not that config JSON, is the TicketStore capability. Provisioning/epoch validation is an explicit new E administrative operation BEFORE any grant issuance, not per-leaf setup; it may not inventory/read original resources, launch children or obtain original authority. Missing/foreign/changed store blocks, never auto-mkdir/fallback in issue/open_leaf. Original and TEST have distinct parent capabilities/generations and types; TEST fixtures use harmless temporary stores only.

Store capability retains a bounded no-symlink component chain from filesystem root using the R2 F3 policy (max32 components/4096pathbytes, no dot/dotdot/repeatedseparators, descriptor-relative opens/link checks). Trusted exclusive namespace/unchanged mount assumptions and residual rename/change-and-restore limitations are EXACTLY R2's; no stronger atomic-path assertion. Existing selected same-actor trusted-host premise is explicit, not a new privileged service/UID0 requirement. There is no claim to resist a malicious trusted store owner deleting durable records. No runtime API deletes/replaces any ticket or issues a capability from stat/path facts.

Provisioned metadata is a bounded fixed schema (<=4096bytes, exact version/kind/generation/owner/bootidentity, no nested/arbitrary records); source-approved read/verify only, no per-leaf ledger dependency. Store administration/creation is separately source-reviewed/trusted ROOT setup with its own finite administrative budget and no original grants. Production generation changes require explicit separate ROOT decision, new immutable source-bound config and preservation of old store/history; never reuse/reissue identifiers from a prior generation. On host boot mismatch/unproved storage recovery, ALL execution/issuance under old generation blocks; no copying records to manufacture recovery. A pre-provisioned regular0600 issuer.lock is opened no-follow under the retained store and held with nonblocking exclusive flock from capacity validation through the whole issued leaf/ROOT safety diagnosis. This actual lock serializes distinct-key issuances/capacity checks and supplies the selected one-active-leaf store policy; lock release NEVER unspends a permanent ticket. Foreign/busy/retargeted lock refuses without per-leaf effects. The generation metadata and lock are not ticket entries. Finite capacity is<=256 permanent tickets per generation; capacity/exact inventory check is bounded prior trusted provisioning/issuance metadata, no unbounded walk. Full capacity BLOCKS, no garbage collection/new generation automatically. Actual private store setup is not done here.

## Stable identifier and binding

Stable filename key is SHA256 of length-prefixed exact ASCII `(version, kind, store_generation, ROOT_grant_id)`; each field source-defined/nonempty<=128bytes, total<=512. Name is64lowerhex plus `.spent`. It deliberately EXCLUDES invocation time, random nonce, current source/plan/leaf/budget: changing those fields under SAME grant ID must collide/refuse, not mint another ticket. New grant ID requires a distinct explicit ROOT authorization, never caller text/renaming a copied file; no issued grant ID is reused after restart/completion/failure/generation change. A test ID is TEST-only and cannot address an ORIGINAL store/type.

The fixed binding hashes exact approved source/deployment/plan/one-leaf/root-decision/budget digests, issuer store/generation/actor/kind, leaf identifier, SAME monotonic origin/end and selected boot identity. Input model is fixed typed fields (six64hex digests, identifiers<=128ASCII, signed-nonnegative64bit times, exact enums); source code constructs it from its actual reviewed issuer state, not arbitrary JSON objects. Hash updates use unambiguous bounded length-prefixes, <=4096bytes total, no user hooks/unbounded serializer. The file payload is fixed ASCII header/version, stable_key and binding_digest plus LF, <=256bytes. No content is parsed later to recreate authority; valid content is diagnostics/collision provenance only. A different binding at an existing key is still consumed/foreign, not a replaceable stale slot.

## Pre-effect budget and durable consume

A single source-owned cumulative book begins at the reviewed earlier pre-effect invocation origin BEFORE issuer operations. It initially permits ONLY issuance/bootstrap under the actual ROOT-or-TEST admission, not any parent/setup/launch/ledger permission. Reserve/spend bootstrap maxima before store/claim effects from THAT SAME book: no separate clock/remaining-credit reset at grant delivery. Future LeafAccount is the SAME book/issuer generation, now activated only after durable handoff; origin/end and all issuance cost remain counted.

Reviewed bootstrap ceiling (task may tighten): wall remaining<=selected immutable absolute end and issuance stage<=2seconds from its own earlier stage origin (never extends leaf end);<=1024 filesystem/time-check syscalls and<=65536 fixed-field/directory/hash validation work units,<=64KiB actual issuer file read/write,<=64 retained source/store/claim fds,<=256byte ticket,<=4096byte fixed binding, and bounded<=256-ticket capacity accounting. Reserve its known cleanup cost within the same book. Check actual time.monotonic_ns/source/store identity before/after each bounded operation. No child/process/socket/worker/private-resource read. Local fsync is not preemptible/hard real-time: post-call expiry HALTs and denies capability delivery; no claim of bounded hardware latency. If common budget cannot fund this reservation, no ticket attempt/capability/setup.

Ticket creation: actual retained store-relative O_RDWR|O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC,0o600; capture regular single-link owned inode, nonblocking exclusive flock, positive bounded write of<=256byte payload (<=16attempts), fsync(file), fsync(storeparent), revalidate all retained links/identity/source/clock and exact same-fd bounded readback. NEVER unlink on any error; even zero-length/partial/unknown tombstone is permanently consumed. The namespace O_EXCL point linearizes competing issuers. Durable COMMITTED point is completed successful file+parent fsync/readback/current-identity sequence, recorded privately before constructing a grant. A competing/restarted process receives EEXIST/collision and zero downstream bootstrap permits, irrespective of content/lock release or ledger absence. Lock is not replay protection; permanent name is.

If fsync/write/readback/result/source/clock fails, outcome is ISSUANCE_FAILED or ISSUANCE_UNKNOWN with exact effects/partial marker diagnostics and full reservation spent. NO actual grant object/parent/create/setup permit is delivered. No in-source retry, claim repair, re-fsync/parse-existing recovery or repeated issue. A process lost before durable COMMITTED cannot have handed authority onward; if created, tombstone rejects replay. A process lost before creating any marker has issued NO grant/authorized leaf, so the preliminary request/copy cannot bootstrap anything. Any future ROOT disposition of that issuance uncertainty is a NEW explicit authorization decision, never automatic acceptance of an old grant or controller restart. Across reboot, old-generation mismatch quarantines instead of trusting an absent non-fsynced claim.

After COMMITTED, issuer stores a private issuance record and constructs one opaque noncopyable/nonserializable NEWRootGrantFile (or disjoint TestGrant) retaining the ACTUAL ticket fd/store capability/exclusive issuer context/SAME book. Exact object/type/root/account/generation/leaf/source/plan/budget/clock bindings are checked at trusted handoff. No path/constructor/public factory can rebuild it in another process. open_leaf consumes its private handoff latch BEFORE issuing ANY parent/ledger/setup permit; repeat/foreign/copy/late/stale/lost handoff refuses. A failure during handoff/activation leaves permanent spent ticket; no second grant or account. Closing fds or dying never unspends the name.

## Linking the evidence ledger without circular authority

After consumed live grant activation, existing F1 LeafAccount.reserve_ledger_operation may issue acquire-parent/create-ledger/update permits. The first LedgerRecordV1 facts include stable ticket key/binding/source/generation/sequence and diagnostic actual issuance proof, but account advancement relies on retained actual issuer history/capability, NOT that JSON. Missing evidence parent/ledger/initial charge or lost first result does not remove ticket or permit newProcess entry. Initial ledger write failure HALTs, no reclaim/retry even when the evidence tree is absent. Stop/export/physical/logical release continue to require their existing actual internal capabilities; the ticket only permits ONE bounded leaf to begin.

Ticket fd/parent remain held through logical leaf completion or root safety diagnosis; final close releases descriptors only. Ticket persists forever in its generation after COMPLETE, HALT, unknown, report loss or process death. No public report returns this capability. The same source-owned account/absolute envelope/logical owner remains through actual P64 flow and audit; no alternate session/budget. Root safety close/release does not turn issuance failure into original success.

## Supported restart boundary

Process restart is never capability recovery: runtime cannot take a grantfile/ledger/ticket path as input. Original issuer cannot reissue any existing stable key; TEST public CLI with same harmless logical ID/store must also refuse. All old issued/possibly-issued grants remain dead. A preliminary root request is not serialized live grant authority. Host reboot/failure of stable local fsync assumptions is handled by generation quarantine and NEW separate ROOT administration; no automatic replay/recovery is claimed. This is a finite local issuer and explicit trust/support policy, not an unspecified external service or an impossible guarantee before the first durable operation.
