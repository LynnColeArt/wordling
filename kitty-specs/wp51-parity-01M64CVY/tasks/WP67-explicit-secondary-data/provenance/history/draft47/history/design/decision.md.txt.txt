## Options and decision

1. Keep only mutable Inspection tables: safe current observation, but consumers must repeat the shape proof and can accidentally accept forged/copied JSON or missing=empty. No production data guarantee results.
2. Add an executable Secondary Program, count-minus-one rule or interpreter now: reject. Count/tail/formatter and host/native materialization are unproved; public inspection is not execution authority.
3. Add the new proof inside native(V), depending on53(W): reject. Installed pure compute actually reports V→W→V cycle. Claiming both V code and W consumer merges old lanes/changes IDs; zero independent collapse does not make that safe.
4. New sibling package plus amendment of existing53 consumer: semantically coherent W→V, but **not task-ready**. Primary lacks the existing literal script; honest owned-file validation fails. Its AUTHORITY_SHA/source_files/exact16Go/module/three-local-package closure also requires explicit migration, not just a helper import. No fake create_intent, glob evasion, tool patch, source overlay or early code merge is allowed.
5. **Selected for independent review:** new sibling production package and genuinely new, separately named research qualification workflow, preserving old53 source/helper/authority/reports/raw inputs byte-exact. It makes the production proof usable by an actual new maintainer workflow rather than cloning the old observer or inventing a product QoL command. It requires a NEW execution lane; do not force24.

This is a necessary domain increment, not an end-user merge feature. If independent review concludes the new workflow merely duplicates an observer/test wrapper without operational value, reject option5 and keep implementation/task authoring blocked; do not manufacture a user CLI to justify the library.

## Proposed public boundary — not an existing API

New package `internal/merge/explicit`, importing only approved `native` plus standard library. It must NOT read private native fields or implement a second framing/token/operand decoder. It can protect source ownership using the actual public API: copy the caller's entire native.View value ONCE, call that captured value's Inspect, compare its Source with the caller's expected opaque native.Source, then use only that captured View.Bytes and its source-owned spans. Whole-value copying preserves the private immutable backing pointer without accessing it. Equal-byte independent Parse is a different source; JSON hashes are custody diagnostics only.

Minimal proposed API:

- `Admit(view *native.View, expected native.Source) (Data, error)`: nil/zero/role/source mismatch refuses atomically. Returns a VALUE with private immutable proof/backing, not a native.Program or pointer to the caller wrapper.
- `Data.Source()`, `Data.RecordCount()` and `Data.Field(recordOrdinal, fieldOrdinal) (Value,error)`: one-based explicit ordinals. RecordCount counts fully delimited EOR records, never interprets their StoredCount. A missing/out-of-range field returns an invalid value AND a typed ExplicitFieldMissing error, never an empty value.
- `Value.Valid()`, `Value.Bytes() ([]byte,error)`, `Value.ExplicitlyEmpty() (bool,error)` and copied provenance getters using existing native.Source/Span/Record/Field values. ExplicitlyEmpty means valid, own EF and zero content length; it is not a general IF BLANK/whitespace evaluator. Nil byte slices alone are never a presence signal. Zero/foreign/invalid handles refuse with typed errors.
- Copied qualification/provenance metadata retains raw count, tail, EF/HR/EOR and opaque D4/hardpage spans plus existing unresolved findings and scope `explicit-field-DATA-only`. No API accepts mutable Inspection/Record/Field/JSON/expected output tables as authority. No export writer, evaluator, IO, resource resolver, current-app adoption, admission-to-Program conversion or target document authority.

Data and Value capture private proof state by value; getters return defensive copies. Captured native.View and its copied Inspection are private and never returned as mutable internal authority. Replacement of Image/View/public result wrappers before admission mismatches expected source; after capture cannot retarget accepted Data/Value. Caller unsynchronized mutation during the capture call is outside the Go contract, consistent with approved50. Subsequent immutable concurrent reads need actual race tests. No duplicate native IR: retain reader-owned span structure and its immutable view, not a second decoded document model.

## Closed predicate and what it proves

Validate the whole requested Secondary body, not a few convenient fields or a finding-code allowlist:

1. Captured valid Secondary role, expected Source.Equal, uncapped findings and positive inherited reader limits. No Primary/Result, nested command, unqualified function/character, incomplete record or unexpected finding is accepted.
2. Contiguous complete record coverage from actual reader body start through EOF. Exactly one or two explicit EF-delimited fields per record, in order; content bytes are printable ASCII and either zero length or not entirely spaces. Preserve bytes exactly: no trimming/coercion. Literal tilde or other existing unqualified findings still refuse; multiline/format-bearing/control fields/all-space fields remain outside profile.
3. Each actual Content ends at actual eight-byte DE31/L4 EF, followed by exactly one owned0A. No arbitrary HR, space, D4 or0C stripping. Existing raw spans/source validate every boundary. Empty tail stays a valid zero-length UNADDRESSED span. Nonempty/unterminated tail refuses.
4. Exact ten-byte DE34/L6 EOR, with only the two independently observed literal shape pairs `(raw2, oneEF)` and `(raw3,twoEF)`. This is a closed cohort discriminator, NOT a calculation, explanation or reinterpretation of the SDK count. Never use StoredCount to bound Field lookup or synthesize implicit entries.
5. Each EOR has exactly the observed contiguous post-record pair: complete32-byte D4/00 owner equal to one of the SIX source-mapped opaque octet profiles, then actual0C. No arbitrary prefix/cache/hash/name check, location guessing, payload meaning or normalization. Every attachment remains owned/copied in provenance; accepting it as opaque data does NOT declare it dead/ignorable or authorize formatter removal/output generation. The two broader unwitnessed profiles and any changed/relocated/missing/extra attachment refuse until separately justified.
6. No token/byte gap or unowned trailing data. A missing shape anywhere refuses the entire Data result, not a partial record set. Preserve all raw source bytes and all original findings. Generic native.Supported/Admit/Program rules are unchanged.

This proves only which already-explicit content spans can be read as source-bound values. It deliberately does NOT prove universal count/tail/addressability, trimmed-space blankness, command evaluation, pagination, formatter output, or how an original merge handles requests beyond explicit fields. A changed ordinary ASCII value such as Clara must pass the structural data predicate with new source identity; it is synthetic structural evidence, not a newly observed original output. No original fixture hash/path/name is an admission condition.
