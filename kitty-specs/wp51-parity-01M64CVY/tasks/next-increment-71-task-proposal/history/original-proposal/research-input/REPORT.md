## Smallest useful slice

An H-only, source-owned horizontal follow-cursor window for a **whole-current-revision, code-free printable ASCII document** is possible using existing approved APIs. It can remove the current cursor>4096 refusal without a new E interface, shadow document, parser, writer, cursor relocation or layout engine. It is a bounded Linux presentation improvement toward M1, **not an observed original long-line scrolling algorithm**. The existing evidence does not establish original scroll thresholds or behavior after thousands of characters.

Preserve its actual row/caret/footer decisions rather than taking any unimplemented layout API for granted. No dependency from E back into H is needed.

## Safe qualification and coordinates

A nonzero window is sound for plain ASCII only after checking the **entire captured revision**, not just the window or prefix sampled around the cursor. Public Token/Kind or bounded Present chunks suffice. Do not inspect native bytes or infer code absence from a filename, hash, body size, editable admission, successful save, empty current window or prior revision. A predicate may store only a view-derived fact bound to the actual comparable NativeRevision; it grants no editing, history, movement or IO permission. Whole qualification must reject any Bold/opaque/HR/HP/non-ASCII owner, including outside the visible window. Empty document is a valid ASCII boundary case.

This does entail finite whole-revision inspection. Existing API caps it at MaxTokens but does not provide a cheap whole-ASCII predicate. A future task must specify an honest qualification-work ceiling and cache/invalidation policy before implementation, or explicitly refuse above a smaller **host presentation** ceiling. Neither repeated full-body copies nor unbounded per-View scans nor arbitrary persistent cache growth are justified. Token-by-token classification stops at the first non-ASCII owner; an opaque Token may copy a large complete owner, so count/temporary-byte/time limits must include that work. No timing or allocation performance is established by this static assessment. This is an H implementation concern, not evidence that a new E framework is required.

For a qualified captured revision, select a complete-token interval [start,end] containing the real cursor gap, with 0<=start<=gap<=end<=total and count=end-start<=4096. Existing model width is bounded1..4096. A stateless cell interval based on actual gap/width can keep the cursor visible without a second document cursor; exact centering/hysteresis is a later reviewed Linux view policy, not original geometry. Use absolute Element.TokenIndex for cursor comparisons, and local `gap-start`/counted ASCII cells for caret/clipping. At true EOF append the existing active blank only when gap==total; end-of-window is not EOF. Reserve the actual caret cell so a full-width prefix does not hide EOF. Windows must include the token at a non-EOF active gap. Both normal and Reveal panes derive from the same presentation and start coordinate; derive no arbitrary numeric native offset from token index.

## Preserve existing other modes

The smallest slice is healthy ordinary Editing, with no selection, no virtual/history/deletion question, pending/detached IO, reconciliation, macro worker or display-suppression state. Qualification failure keeps the existing explicit path/refusal/partial inspection. This is a view dispatch restriction, not a new reducer restriction on otherwise admitted commands.

* Bold: Present provides codes in the window, not Bold-at-entry. A BoldOn before start can affect an apparently ASCII window. Do not default plain and do not scan/reimplement prefix formatting semantics. Existing short Bold view remains intact through the old path; long Bold remains an explicit gap.
* Selection: current marker checks compare local i to absolute selection endpoints. Preserve the existing bounded path; do not partially show a selected range as though complete. No new block authority.
* HistoryPreview: `internal/document/history.go:392–455` provides a different virtual Overlay. DocumentToken.TokenIndex and DeletionFragment.TokenIndex have different coordinate origins; fragments have absent native spans, while FragmentStart/End are virtual positions. `editor/editing.go:88–90` already forwards Preview, but current H intentionally synthesizes no-native-span elements. A plain-document viewport must never reinterpret this overlay as native owners. Leave preview limits unchanged.
* Partial Reveal: `reveal_inspection.go:liveInspectionFrame` authenticates InspectRevealCatalogue on the same revision before legacy Present, uses initial window0/count, and falls back ONLY on UnsupportedToken. It has its own bounds/TrueEOF and no movement authority. Keep this path unchanged. Do not make a cursor-follow window silently erase unsupported owners from partial diagnostics.
* Frozen macro: `visibleFrame()` returns frozen frame AND inspection before any live inspection when DISPLAY is suppressed; macroStart captures that frame. A new viewport must remain inside this selection order. Resize, live revision/window changes or State must not recompute frozen pixels/caret/inspection from live state. MacroNew/actual sink semantics remain unchanged.
* Public caller/stale models: `Model.Update` owns runtime UI transition claims, State/View are observations; no independently forked Session may execute intents. Do not let a cached qualification/window grant authority to a stale model. Captured Session/Revision consistency matters across copied wrappers, edits, retrieve, first binding, Doc1/Doc2 and source replacement. Pending and error notices remain visible; no new filesystem effects to 'refresh' a view.
