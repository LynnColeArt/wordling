Two key-routing positions and one lifecycle prelude are necessary, rather than a stand-alone unused string helper:

1. Inside authentic update, before existing async/admin switching, inspect a pending character state for context-changing nonkey messages. Invalidate ONLY that state when required and continue existing reply/control dispatch. Never swallow/rewrite/detach a genuine receipt, start a worker or clear genuine uncertainty. Env/color/capability/version and release are explicitly neutral; paste/unknown/resize/focus/mouse and actual host async/control invalidate. Startup dimensions/capabilities before admission are normal existing input. No count state exists on legacy contexts.
2. For a translated Press with character state pending, handle it BEFORE menuPress. First revalidate real context/current UI and reject IsRepeat/modifier/multi-text/unsupported inputs. This branch may consume only the pending operation's key; it must apply actual source/IO/macro/menu gates before it can return ahead of the old later guards. Alt+= and AltF10 are unsupported pending inputs, produce no menu/macro action and invalidate the count. The pristine menu exclusion and New-macro-repeat exclusion tests stay true.
3. Initial Esc admission is AFTER the old menu/reconciliation/detached-IO/IsRepeat checks and BEFORE macroKey. Admission is allowed only for the strict pristine context. If not admitted, do not reinterpret loaded/new invalid contexts: continue the old macroKey path and its existing refusals. This keeps loaded Esc3→AltF10 exact. A successful character completion clears only its transient state and calls `m.reduce(Text)` ONCE; ordinary dispatch is not also run for the same key. The authentic Update wrapper then performs normal menu/cache work.

Calling claimUI again in a helper would consume authority incorrectly; use the already claimed Model's actual runtime pointer/token comparison. A stale Model's failed outer claim returns before any character state transition, expansion or native work. Captured UI token cannot be compared unchanged across inputs, because each legitimate Update advances it. Instead every step requires the returned chain's current token plus the unchanged captured opaque native/genesis context. Copying a pending Model can copy data, never the right to consume it after the current chain advances. Do not share a mutable pointed count between persistent values.

These are the existing menuReason and newMacroHostIdle safety facts plus explicit New Birth/history/owner checks; continuing checks must observe them directly without clearing/zeroing copied Model or Session fields to trick the old menu/macro predicates. The new pending state itself legitimately makes menu/macro unavailable, so do not call a predicate that rejects it and then “fix” that result by resetting a Model copy. Local pure read-only common extraction is unnecessary for this bounded change; no broader predicate framework/refactor is authorized. Duplicated explicit guard checks are acceptable if tested by behavior. Initial helper may use existing menuReason as a supplemental check, never as a replacement for the stronger stated facts.

No source/session/history baseline is reset on cancellation. Cancellation leaves the actual constructor context but installs a truthful host diagnostic; it does not erase evidence that a key was refused. Ordinary future admitted text can clear notices through the inherited reducer exactly as before. Repeated Escape while pending cancels; it does not restart or install default8. No requirement to resume character Repeat after an error without a new genuine startup.

## Allocation and atomicity

The grammar bounds count at9 from its creation; never accumulate an arbitrary decimal string or parse an unbounded integer. A second digit invalidates before numeric operations. Validate state/count/current document and subtract-based downstream token/native-byte capacity before constructing payload. Export length is from genuine immutable document; only this small pristine profile is eligible. No E catalogue/classification/window is needed to establish empty real New identity.

One count-sized ASCII string feeds the existing Text path; downstream []byte conversion, InsertASCII and publishBody remain the one authoritative mutation/writer. Existing Text updates history through its actual edit receipt, copies native revision and advances cursor. Do not assert DOS internal grouping/revision counts: new tests assert the existing host single-Text contract and conserved native output. No direct native revision/prefix patch, separate history engine or transaction rollback. An error returns the old immutable document and leaves no partial published count. No IO intent should arise from Text in this cohort; an unexpected actual intent is an acceptance failure, not permission to execute it speculatively.

The rejected alternative—using loaded MacroRepeat3, cloning/resetting Session or direct Document.InsertASCII—would either trip the actual non-Macro guard, weaken New exclusion or bypass authoritative receipts. A broader general repeat command/API/count parser is not necessary for the observed positive and would introduce unsupported semantics. A UI-only value state plus one actual Text transition is the smallest production composition.
