# Prospective host limits and atomic refusal

These are selected conservative Linux implementation limits for TASK review, not original DOS capacities, existing source guarantees, a sandbox or allocation measurements. They may be tightened only with truthful supported-case consequences; no runtime/campaign growth. Implementation must demonstrate the arithmetic against real source/type sizes and measured allocated bytes, not assert the ceilings are already proved.

| Scope | Ceiling / pre-effect rule |
|---|---|
| Existing native admission | Preserve exact approved positive Limits and MaxBytes1MiB/MaxTokens65536/MaxRecords4096/MaxFields16384/MaxOperand256/MaxFindings1024/MaxDepth64; no mutation or replacement reader. |
| New primary compile | ≤4096 tokens after one authenticated Inspect; exactly1 command in FormA or4 in FormB; entire role/source/findings/token/command/operand/end coverage checked, iterative only. |
| Inherited inspection allocation | Program exposes no count-only preflight API: its ONE defensive Inspect may copy the existing native-capped arrays BEFORE new4096-token refusal. Explicitly reserve/charge48MiB and `4*(MaxTokens+MaxFields+MaxRecords+MaxFindings)` work units BEFORE calling it. Prove the fixed conservative reservation covers all actually copied pinned native types/cardinalities; missing proof blocks, no claim new4096 cap prevents the inherited copy. No second full-source copy/Export or repeated Inspect. |
| Compile allocation/work | Fixed cumulative allocation/copy-request budget64MiB including that48MiB inherited allowance; new operations charge remaining before make/append/Bytes and checked products. Selected WorkUnits≤1048576 includes the precharged inspection work and every token/command/span/byte/copy step. Insufficient budget returns invalid Plan before that step. |
| Per-record body | Selected BodyBytes1..65536; compute checked total selected literal+field+terminalHR length BEFORE allocating/appending output. No overflow via multiplication/addition or checking after append. |
| Per-evaluation work | Captured selected WorkUnits1..1048576. Charge each instruction/decision/span validation, byte read/copied/emitted and provenance append before operation. No recursion, loop language, token×command quadratic rescans or implicit whole-data export. |
| Per-evaluation allocation | Fixed cumulative requested/copy bytes≤4MiB, including Value.Bytes, output, trace and defensive result construction. Check authentic field.Content length from Value.Provenance BEFORE allocating Value.Bytes; no copy-then-check. ≤4098 trace entries, matching ≤4096 primary token references plus two field/decision references; no metadata payload copies. Defensive result accessor copies have the same bounded size and do not mutate the proof. |
| Maintainer consumer request | Exactly one primary+secondary payload pair, closed exact JSON with duplicate/unknown/trailing refusal; read at most3MiB+1 sentinel before decode, each decoded native input≤1MiB before Parse. No arbitrary data objects or expected result input. |
| Consumer expansion | ≤32 explicit records, total staged body bytes≤256KiB, total trace entries≤16384, complete encoded stdout≤1MiB; preflight/report-size bound before encoding. Each admitted record evaluated once. A later record's failure publishes no success rows. |
| Consumer work/allocations | Precharge actual native decode/admission costs from their bounded source closure; maintain fixed cumulative64MiB WORK UNITS and256MiB allocation/copy-request envelope across request/read/parse/compile/all evaluations/report. This includes conservative per-Compile64MiB/per-Evaluate4MiB reservation and bounded native/JSON source copies; do not reset per record. Demonstrate actual fit/reservations before positives; insufficient fit refuses, never cap increase. This is not process RSS or all runtime allocation enforcement. |
| Validation execution | Each command≤300s; each new real CLI≤30s+2s owned cleanup and≤2MiB live retained combined stdout/stderr; focused predeclared semantic-control campaign≤180s; evidence≤512files/8MiB, including full retained failures/nested seals. |

Use checked uint64/int arithmetic appropriate to actual Go architecture; reject overflow before make/slice/append/read/copy. Count finite source/trace/copy traversals and prevent hidden repeated whole-inspection/field copies. Report benchmark B/op/allocs/op and bounded maximum-case elapsed as observations separate from conservative reservations; allocator/GC/interpreter/runtime RSS is not inferred from payload length. Concurrent read-only Plan/Data/Result access is supported; concurrent replacement of caller inputs DURING native.Parse/explicit.Admit/Compile capture is outside the existing trusted-caller contract. Subsequent replacement/mutation of wrappers/inspection/results cannot retarget captured ownership.

Atomicity is semantic: on Compile/Evaluate failure no valid/partial Plan or Result escapes; no native/editor state or files change. All consumer results are staged before stdout; an OS stdout failure may have partial written diagnostics and must be failure with truthful retained bytes. No rollback, atomic pipe write or native-save promise is made.
