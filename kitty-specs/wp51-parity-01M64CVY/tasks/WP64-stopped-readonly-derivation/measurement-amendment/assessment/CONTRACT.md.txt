# Proposed bounded measurement transaction and acceptance

This is a proposed narrow amendment, NOT current approved semantics or an implemented algorithm. Required review choice: accept the explicitly bounded sampled-resource gap below, or preserve immediate MeasurementUnknown. No code change is authorized by this packet.

## Compatibility and required explicit policy amendment

Propose a keyword-only immutable SharedEnvelopePolicy field `measurement_completion`, default exact string `strict`, with the ONLY other accepted value `bounded-original-v1`. No-envelope and every existing caller omitting this field (including old envelope callers) keep immediate strict refusal. New mode must be selected prospectively at Session creation, bound in its actual source/policy/wire packet; no per-RPC flag/setter, copied observation or automatic fallback can change it. This is a deliberate ADDITIVE PUBLIC POLICY/SCHEMA amendment, not an existing API or a resource cap increase. Existing open_session three positional args and keyword envelope placement/cap defaults remain. Actual validation must check this selector and ALL old numeric fields explicitly; don't silently rely on the current numeric dataclass-field zip to validate an added nonnumeric field. Foreign/unknown mode/packet or old worker unable to recognize it refuses, never silently uses relaxed behavior.

Wire/source consequences: the SAME worker policy schema gains only optional exact-string measurement_completion; absent meansstrict, explicitstrict is semantically identical, and unknown/nonstring/coerced values refuse. Canonical client encoding omits strict so old callers do not opt in or silently acquire extra wire work; only bounded-original-v1 emits the new field. Existing numeric limits are never omitted/defaulted differently. Actual approved client/worker/facade/root aliases/policy-validator/CLI fixture sources and tests must be freshly frozen, source-bound and reviewed together. Old workers that cannot recognize the new mode refuse it; no downgrade/retry. New source digests change naturally and cannot reuse old grant/root cache authority. The mode is policy DATA, not original authorization, a lease, readiness or permission to clear history. No UsageObservation field/type or resource-budget cap is changed by this proposal; only explicitly documented journal gap evidence and sampled-peak interpretation accompany an opted-in completed measurement. If that evidence cannot be truthfully retained under existing journal limits, refuse rather than truncate or increase limits.

ROOT must first obtain independent design approval and perform guarded canonical64/task/contract amendment with fresh current analysis before any source implementation or new tests. The frozen positive fixture remains strict/failed as captured; it cannot be retrospectively declared opted in. A future positive in the new mode is a NEW source-frozen TEST invocation after those gates, not an old RPC retry or grant. If additive mode or sampled-gap semantics are rejected, choose strict refusal and do not implement successful grace.

## Eligibility and one held transaction

Only an envelope with the NEW explicitly selected mode and worker-held current ORIGINAL direct-child lease may enter the pending branch, before ANY first_fault is latched. No generic PID argument/caller fact can select it. The worker must already retain that child's causal spawn, birth/startticks, pidfd/unreaped ownership, epoch/session and source identity. Both available before/after stat records must name the SAME retained birth; the first cause must be fd-enumeration EACCES/ENOENT/ESRCH only, not malformed/birth-reused/missing-stat/source/exec/argv/credential/control error. This does NOT label that process dead, known live or measured0. Coordinator/worker/helper/unknown descendant census failures remain immediate refusing in this narrow proposal. No allowance for the two unexplained earlier failures is inferred.

Worker ownership layer manages this branch, where actual causal records exist; a generic sampler must NOT loop based only on PID/state/RSS facts. No engine-level change makes all errors retryable. Once any fault is already latched, no pending branch is entered; existing first-fault containment/unknown behavior wins. A raw unsuccessful read is called pending only by the NEW reviewed rule; an existing raised/latched MeasurementUnknown is never renamed retroactively.

One held RPC/monitor measurement transaction gets **at most3 complete census attempts TOTAL**, including the first failed attempt. Absolute transaction end is min(first attempt origin+10ms, ALL already-selected earlier session/leaf/command/child/publication/readiness deadlines that actually apply). It is not reset per actor/read/poll/progress. This10ms ceiling is a proposed source policy aligned with the existing nominal sampling interval, NOT a measured OS timing guarantee. Each optional sleep<=1ms and bounded by remaining existing time. Before/after every attempt and wait check actual monotonic clock, all source/root/current retained identity guards, first_fault, parent pidfd, control-channel loss, existing budget/work/poll/journal/output/response constraints. Do not recursively invoke a monitor that restarts its own measurement window; keep one source-owned deadline/attempt counter.

All attempts and source scans count toward existing poll/work/source/journal budgets. No cap increase, resetting last_sample early to suppress monitoring, new response reservation, clearing lost-response spend, second RPC/session/worker, or expanded source/resource permission. If existing remaining credit/deadline cannot fund an attempt, fail under the actual selected limit. A blocking /proc/source syscall can overshoot; fresh after-call checks deny success/later effects, not claim hard real-time preemption.

During pending measurement: no protocol command, capability/readiness/current identity publication, helper launch, mutation, stopped seal/derivation/output lease or successful RPC response. Existing bounded stream draining/source/loss/clock checks may continue only under their SAME supervisor/counters so output/control backpressure is not hidden. A discovered output/resource/source/lifetime/parent/control fault is immediately sticky and cannot be waited away. Any prior completed measured violation remains a violation; do not retry until a smaller sample appears.

Do not manufacture WNOWAIT, substitute a copied ExitObservation or reap through an unrelated API. Actual nonzero/signalled exit still follows its existing fault rule. At attempt/time exhaustion, persistently live-unobservable actor, ambiguous birth/exit/membership, parent/worker/control loss, source/root change or unpublishable diagnostics: MeasurementUnknown or the actual earlier sticky failure, SAME conservative outstanding response spending and existing containment; no derived handles. A worker crash means client loss/unknown, not an opportunity to recreate the transaction. Diagnostic-only remeasurement after a latched fault may never restore success and must not introduce further operational effects.

## Missing peak/exposure policy is explicit

The unavailable interval has UNOBSERVED FD/RSS/process values. Do NOT fill it with0, last sample, selected cap or later terminal current values. A later complete census proves its own instantaneous values only. Observed peak fields remain max of actual completed samples; they do not become a continuous-time or unknown-interval bound. Journal records first unsuccessful read, attempt count/interval, actual kernel/accessible resolution or terminal failure and final observation time. It retains uncertainty rather than certifying resource use never exceeded caps. This proposal does not add public Usage fields, redefine observed numbers as upper bounds or refund credits based on unavailable history.

Current contract's fail-on-unobservable rule avoids accepting that gap; allowing this bounded pending interval IS a normative relaxation. If independent review requires every failed scheduled sample to remain resource-unusable, there is no success-producing grace that preserves that requirement: retain immediate refusal. Future introduction of a separately enforced trustworthy upper-bound provider would be a different scope, NOT assumed here. No rlimit/cgroup/zero-mm claim supplies an unimplemented proof.
